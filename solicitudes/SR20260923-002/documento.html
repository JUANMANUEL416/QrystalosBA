Artículo comercial: el servicio queda en otro fabricante

Necesidad para el plan de trabajo. No es un dictamen de implementación.

SR20260923-002
Transversal (producto Qrystalos)
2026-09-23
Para comité

1. Necesidad o problema

El artículo de un fabricante debe nacer y permanecer con el servicio del artículo principal. Si hoy queda con el código de otro fabricante, el catálogo debe impedirlo y debe poder corregirse en la misma pantalla.

2. Análisis

Paso 0. No es capacitación. El alta de fabricante y Transferir artículo existen. El defecto es el valor que queda en IART.IDSERVICIO.

DESAIX: PREVERSION idéntica a la Cerrada 2.0.3 (anterior 2.0.2). El arreglo no está en canasta.

Qué hace hoy.
- SPQ_IART · TRANSFERIR_ARTICULO escribe el IDARTICULO destino en IART.IDSERVICIO del origen y copia ese código a SER.IDREFERENCIA. Eso explica a varios comerciales de la misma familia apuntando al mismo hermano (DM0061-1 y DM0061-2 apuntan a DM0061-3; MX1266-1 apunta a MX1266-2).
- SPQ_IART · INSERTAR_HERMANO copia el IDSERVICIO del principal. Si el principal ya está bien, el hijo nace bien. No rechaza un servicio que sea código de otro artículo.
- SPQ_IMOV_3 · GUARDA_FABRICANTE graba el IDSERVICIO que viene en pantalla.
- SPQ_IMOV_3 · NUEVO_FABRICANTE, si el código alterno existe en SER, hace UPDATE IART SET IDSERVICIO = ese código. El consecutivo lo busca con SER.IDARTICULO = código alterno, no con el servicio del principal.

Dato. Consulta de solo lectura del 2026-09-23. CEM: 112. PCEM: 1. Los 113 tienen IDSERVICIO igual al IDARTICULO de otro artículo y distinto del servicio del principal. Ninguno apunta a su propio código. El servicio del principal existe en SER y no es DEINVNODESER (en CEM y PCEM, DEINVNODESER = NA).

Clasificación. Defecto de SQL y de la pantalla de artículos por fabricante. Sin cambio de contabilidad.

3. Alcance

Incluye SPQ_IART (TRANSFERIR_ARTICULO, INSERTAR_HERMANO y dos métodos nuevos para listar y corregir) y SPQ_IMOV_3 (GUARDA_FABRICANTE y NUEVO_FABRICANTE). Incluye el aviso y el botón Corregir en artículos por fabricante. El script de datos corrige los cruzados ya guardados y no forma parte del desarrollo.

4. Restricciones

Publicar en preversión. No ejecutar el script de datos desde BA ni en CEM hasta revisar la vista previa. No modifica SER, kardex ni el artículo principal. No corrige un comercial cuyo principal no tenga servicio en SER o tenga el servicio DEINVNODESER.

5. Criterios

1) Al crear un comercial de MX1266, IART.IDSERVICIO queda MX1266, igual al principal, aunque en pantalla llegue MX1266-2.
2) Al transferir MX1266-1 hacia MX1266-2, el servicio de MX1266-1 sigue o vuelve a MX1266. El sistema no guarda MX1266-2 en IDSERVICIO.
3) Si el destino es de otra familia, la transferencia se rechaza con mensaje claro.
4) En el catálogo, MX1266-1 muestra el aviso y Corregir lo deja en MX1266 sin tocar a MX1266 ni a MX1266-2.
5) El listado de cruzados, en una copia de CEM, devuelve los 112 y, al corregir, queda en cero con la misma regla del script.
6) Un comercial que ya tiene el servicio del principal no cambia.

6. Recomendación

Llevar al comité el control en el alta y en la transferencia, y el botón Corregir en el catálogo. Los fragmentos están en la sugerencia SQL. Quien valida los prueba en preversión con la familia MX1266. El script de datos (vista previa con @APLICAR = 0) queda para corregir CEM y PCEM mientras el desarrollo no está publicado. No se ejecutó.

Especificación para el comité y el desarrollador. No ejecutar desde BA. Contrastar PREVERSION vs última Cerrada antes de implementar.

-- Especificación. No ejecutar desde BA.
-- DESAIX: PREVERSION idéntica a la Cerrada 2.0.3 (anterior 2.0.2). El arreglo no está en canasta.
-- Cuerpos leídos: solicitudes/SR20260923-002/sql/SPQ_IART.sql y SPQ_IMOV_3.sql
-- Corrección de datos, aparte del desarrollo: solicitudes/SR20260923-002/sql/CORRECCION_IART_IDSERVICIO_HERMANO.sql

-- 1) SPQ_IART · TRANSFERIR_ARTICULO
-- Hoy guarda el código del artículo destino en el servicio del origen.
-- ANTES:
UPDATE IART SET IDSERVICIO = @IDARTICULO_DES WHERE IDARTICULO = @IDARTICULO_ORI
UPDATE SER SET IDREFERENCIA = @IDARTICULO_DES WHERE IDSERVICIO = @IDARTICULO_ORI
-- QUEDA: el servicio del origen es el servicio del principal de la familia.
-- Rechaza si el destino es de otra familia o si el principal no tiene servicio real
-- (vacío o igual a DEINVNODESER). No escribe el IDARTICULO destino en IDSERVICIO.
DECLARE @BASE_ORI VARCHAR(20), @BASE_DES VARCHAR(20), @IDSERVICIO_PRIN VARCHAR(20)
SET @BASE_ORI = CASE WHEN CHARINDEX('-', @IDARTICULO_ORI) > 0
  THEN LEFT(@IDARTICULO_ORI, LEN(@IDARTICULO_ORI) - CHARINDEX('-', REVERSE(@IDARTICULO_ORI)))
  ELSE @IDARTICULO_ORI END
SET @BASE_DES = CASE WHEN CHARINDEX('-', @IDARTICULO_DES) > 0
  THEN LEFT(@IDARTICULO_DES, LEN(@IDARTICULO_DES) - CHARINDEX('-', REVERSE(@IDARTICULO_DES)))
  ELSE @IDARTICULO_DES END
IF @BASE_ORI <> @BASE_DES
BEGIN
  SELECT 'KO' OK
  SELECT 'El artículo destino no es de la misma familia.' ERROR
  RETURN
END
SELECT @IDSERVICIO_PRIN = LTRIM(RTRIM(IDSERVICIO))
FROM IART
WHERE IDARTICULO = @BASE_ORI AND COALESCE(PRINCIPAL, 0) = 1
IF NULLIF(@IDSERVICIO_PRIN, '') IS NULL
   OR @IDSERVICIO_PRIN = LTRIM(RTRIM(DBO.FNK_VALORVARIABLE('DEINVNODESER')))
   OR NOT EXISTS (SELECT 1 FROM SER WHERE IDSERVICIO = @IDSERVICIO_PRIN)
BEGIN
  SELECT 'KO' OK
  SELECT 'El principal no tiene un servicio válido para el comercial.' ERROR
  RETURN
END
UPDATE IART SET IDSERVICIO = @IDSERVICIO_PRIN WHERE IDARTICULO = @IDARTICULO_ORI

-- 2) SPQ_IART · INSERTAR_HERMANO y SPQ_IMOV_3 · GUARDA_FABRICANTE
-- El INSERT del hijo debe tomar IART.IDSERVICIO del principal (PRINCIPAL=1),
-- no el valor que venga en el JSON ni el de un hermano ya cruzado.
-- Si ese servicio es el código de otro artículo, rechazar:
--   'El servicio del comercial no puede ser el código de otro artículo.'

-- 3) SPQ_IMOV_3 · NUEVO_FABRICANTE
-- Quitar este UPDATE (reescribe el servicio con el código alterno):
UPDATE IART SET IDSERVICIO = @IDALTERNA
WHERE IART.IDARTICULO = @IDALTERNA AND IART.IDSERVICIO <> @IDALTERNA
-- El consecutivo nuevo se arma con el servicio del principal recibido en IDARTICULO,
-- no con SER.IDARTICULO = IDALTERNA.

-- 4) Corregir desde el catálogo. SPQ_IART, métodos nuevos:
-- LISTAR_IDSERVICIO_CRUZADO: la misma regla del script de datos (familia o todos).
-- CORREGIR_IDSERVICIO_HERMANO: el mismo UPDATE, por un IDARTICULO, por el principal o el listado.
-- La pantalla de artículos por fabricante muestra el aviso y el botón Corregir.

Propuesto (análisis del REQ)

En el alta y en la transferencia, el servicio del comercial queda el del principal y se rechaza si el valor es el código de otro artículo. En el catálogo, un aviso y un botón Corregir aplican esa misma regla a uno, a la familia o al listado. Mientras el desarrollo no está en preversión, el script de datos corrige los que ya están cruzados.
