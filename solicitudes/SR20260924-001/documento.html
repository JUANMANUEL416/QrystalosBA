IART: un CUM solo puede pertenecer a un artículo

Necesidad para el plan de trabajo. No es un dictamen de implementación.

SR20260924-001
COMITE DE ESTUDIOS MEDICOS
2026-09-24
Para comité

1. Necesidad o problema

En el maestro de artículos un código CUM debe identificar un solo artículo. Hoy el mismo CUM está en varios artículos activos, con presentaciones distintas y, en algunos casos, con productos que no son el mismo. Al dispensar o al armar la autorización no se sabe cuál código cobrar. También hay nombres casi iguales que no permiten distinguir el artículo.

2. Análisis

Paso 0. No es capacitación: el usuario conoce el maestro, pero el sistema no impide duplicar CUM ni nombre entre activos. En CEM hay 596 CUM repetidos y 476 con más de un artículo activo.

Ubicación en Qrystalos. Menú Artículos (IART) → control «Artículo y tipo (IART / ITAR / SER)» (proceso inventario, capa 01-configuración, control iart-maestro). El front envía AppStore.json con MODELO IART y METODO GUARDAR (PROCESO INSERTAR o EDITAR). En servidor se ejecuta SPQ_IART.

Estado del backend (ficha conocimiento/inventario/sps.json, cuerpo SPQ_IART GUARDAR). Hoy valida IDARTICULO duplicado en alta manual, PRECNS/MCNS, reglas INTER_SAP al inactivar y sincronía SER con CAMBIO_ART_ESTADO. No valida unicidad de CODCUM ni de DESCRIPCION entre activos: tras parsear JSON inserta o actualiza IART con @CODCUM y @DESCRIPCION sin consulta previa.

Clasificación. Hueco de regla en el maestro. Impacto operativo: al cruzar dispensación con autorización (AUTD), un mismo CUM con varios IDARTICULO activos obliga a elegir manualmente qué cobrar; riesgo de facturar presentación distinta (ej. 20137997 Glucoquick 31G vs 32G; 20035564 sonda vs instrumental).

Alcance técnico mínimo de esta solicitud. Un solo SPQ y un solo METODO: SPQ_IART · GUARDAR (ramas INSERTAR y EDITAR). Frontend: mostrar el texto KO devuelto (sin cambiar el contrato JSON). No incluye índice único en BD hasta limpiar datos. Fuera de alcance salvo decisión del comité: SPQ_IART · GUARDAR con PROCESO INSERTAR_HERMANO (también inserta IART con CODCUM clonado), importaciones masivas u otros METODO que inserten IART sin pasar por las mismas validaciones.

Datos previos. La validación no corrige los repetidos existentes; primero limpieza (un activo por CUM o CUM vacío en los demás). Consulta de control antes de endurecer con índice único: agrupar CODCUM trim entre ESTADO=Activo y HAVING COUNT(*)>1 debe quedar en cero en cada sede/cliente.

3. Alcance

Incluye la validación al crear o editar un artículo activo: CUM único y nombre único entre activos. Incluye el mensaje que muestra el otro artículo. No incluye borrar ni unificar los 596 CUM que ya están repetidos. No cambia las autorizaciones ya copiadas a la sede 07.

4. Restricciones

No crear un índice único de CODCUM mientras existan repetidos: no dejaría guardar ni corregir. La regla aplica a ESTADO Activo. Un artículo inactivo puede conservar el CUM histórico. El CUM vacío no se valida. El nombre se compara ya recortado.

5. Criterios

1) Guardar un artículo activo con un CUM que ya tiene otro activo no graba y muestra el IDARTICULO que lo tiene.
2) El mismo CUM en un artículo inactivo sí deja guardar el activo, si no hay otro activo con ese CUM.
3) Guardar un activo cuyo nombre, ya recortado, es igual al de otro activo no graba y muestra ese código.
4) Un CUM vacío no dispara la validación.
5) En CEM, 20137997, 19908543-4, 20035564, 20125491 y 20256194 siguen pudiendo consultarse. La pantalla no los fusiona sola.

6. Recomendación

Llevar al comité la validación en el maestro de artículos. Un CUM activo, un artículo. Un nombre activo, un artículo. La limpieza de los repetidos de CEM queda como tarea de datos, antes de volver obligatoria la restricción para los que ya existen.

7. Sugerencia de código SQL

Especificación para el comité y el desarrollador. No ejecutar desde BA. Contrastar PREVERSION vs última Cerrada antes de implementar.

Objeto: SPQ_IART, METODO GUARDAR (INSERTAR y EDITAR). Validación en @TBLERRORES antes del INSERT/UPDATE. No índice único en esta entrega.

--- BEFORE (hoy, tras OPENJSON en GUARDAR) ---
No hay bloque que consulte otro IART por CODCUM o DESCRIPCION. En INSERTAR, si no hay errores previos, ejecuta INSERT INTO IART (... CODCUM ...) con @CODCUM. En EDITAR, UPDATE IART SET ... CODCUM=@CODCUM, DESCRIPCION=@DESCRIPCION ... WHERE IDARTICULO=@IDARTICULO.

--- AFTER (especificación) ---
DECLARE @ESTADO_NUE VARCHAR(8) = COALESCE(NULLIF(LTRIM(RTRIM(@ESTADO)), ''), 'Activo');
DECLARE @CUM_NORM VARCHAR(30) = NULLIF(LTRIM(RTRIM(@CODCUM)), '');
DECLARE @DESC_NORM VARCHAR(900) = UPPER(LTRIM(RTRIM(@DESCRIPCION)));

-- 1) CUM único entre activos
IF UPPER(@ESTADO_NUE) = 'ACTIVO' AND @CUM_NORM IS NOT NULL
BEGIN
  DECLARE @ID_CUM_EXISTE VARCHAR(20);
  SELECT TOP 1 @ID_CUM_EXISTE = IDARTICULO
  FROM dbo.IART
  WHERE UPPER(LTRIM(RTRIM(ESTADO))) = 'ACTIVO'
    AND NULLIF(LTRIM(RTRIM(CODCUM)), '') = @CUM_NORM
    AND IDARTICULO <> @IDARTICULO;
  IF @ID_CUM_EXISTE IS NOT NULL
    INSERT INTO @TBLERRORES(ERROR)
    VALUES ('El CUM ' + @CUM_NORM + ' ya está asignado al artículo activo ' + @ID_CUM_EXISTE + '.');
END

-- 2) Nombre único entre activos (trim + mayúsculas)
IF UPPER(@ESTADO_NUE) = 'ACTIVO' AND @DESC_NORM IS NOT NULL
BEGIN
  DECLARE @ID_NOM_EXISTE VARCHAR(20);
  SELECT TOP 1 @ID_NOM_EXISTE = IDARTICULO
  FROM dbo.IART
  WHERE UPPER(LTRIM(RTRIM(ESTADO))) = 'ACTIVO'
    AND UPPER(LTRIM(RTRIM(DESCRIPCION))) = @DESC_NORM
    AND IDARTICULO <> @IDARTICULO;
  IF @ID_NOM_EXISTE IS NOT NULL
    INSERT INTO @TBLERRORES(ERROR)
    VALUES ('Ya existe un artículo activo con el mismo nombre: ' + @ID_NOM_EXISTE + '.');
END

-- Si COUNT(@TBLERRORES)>0 → SELECT 'KO' OK; SELECT ERROR; RETURN (patrón actual).

Ubicar el bloque AFTER: en INSERTAR, después de validar IDARTICULO y antes del INSERT; en EDITAR, después de fijar @ESTADO_NUE y antes del UPDATE.

Consulta de limpieza de datos (CEM u otra sede) antes de índice único opcional:
SELECT LTRIM(RTRIM(CODCUM)) AS CUM, COUNT(*) AS ACTIVOS
FROM dbo.IART
WHERE UPPER(LTRIM(RTRIM(ESTADO))) = 'ACTIVO'
  AND NULLIF(LTRIM(RTRIM(CODCUM)), '') IS NOT NULL
GROUP BY LTRIM(RTRIM(CODCUM))
HAVING COUNT(*) > 1;

8. Normativa y adjuntos

No hay norma adjunta. El CUM es el código del producto dispensado. Un mismo código no puede apuntar a dos presentaciones cobrables.
