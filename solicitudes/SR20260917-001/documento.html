Generación rápida de CxP desde factura Radian (sin cambio de pestaña)

Necesidad para el plan de trabajo. No es un dictamen de implementación.

SR20260917-001
Transversal (producto Qrystalos)
2026-09-24
Para comité

1. Necesidad o problema

Al recibir facturas electrónicas en el tab Facturas Radian, el usuario debe crear la cuenta por pagar de forma ágil. Hoy el sistema obliga a cambiar de pestaña, guardar cabecera manualmente y repetir CC/cuenta en cada factura del mismo proveedor. Se requiere flujo rápido con REGISTRAR_CXP_FRADIAN, homologación por línea (IDTERCERO + código ítem XML) y cuenta crédito de cabecera desde TER (captura si falta).

2. Análisis

Proceso cxp-fcxp. Clasificación: mejora UX + persistencia parametrización Radian.

Entrega única al desarrollador: solicitudes/SR20260917-001/modelo-entrega-desarrollador.html

SQL nuevo:
- Tabla CXP_RADIAN_HOMO (PK: COMPANIA, IDTERCERO, COD_EXT)
- SPQ_FCXP: BUSCAR_HOMOLOGA_RADIAN, GUARDAR_HOMOLOGA_RADIAN
- Ajuste REGISTRAR_CXP_FRADIAN: CUECREDITO desde JSON con fallback TER.CUENTA; KO si vacía

FE:
- FacturasRadianComponent + CxpFradianDetalleContableDialog + preview CUECREDITO

KMCOM/KMCOMS siguen resolviendo cuenta contable por IDSERVICIO+CC cuando falte CUENTA_SER en homologación.

Mockups actualizados. Dictamen F2: dictamenes/20260917-cxp-fcxp-radian.html

3. Alcance

- Tab Facturas Radian (FacturasRadianComponent.vue).
- Modal CC/cuenta + homologación por línea (IDTERCERO + COD_EXT).
- Preview cabecera CUECREDITO (TER.CUENTA / captura / opcional guardar en TER).
- Tabla CXP_RADIAN_HOMO + METODOs BUSCAR/GUARDAR en SPQ_FCXP.
- Ajuste REGISTRAR_CXP_FRADIAN (CUECREDITO JSON).
- REGISTRAR_CXP_FRADIAN + opcional RECONSTRUIR_CUENTAS_FCXPD.
- Fuera: F1 defectos FE (otro ticket), REQ 6349 CUENTAGRAV, VINCULAR_CXP_FRADIAN.

4. Restricciones

- Homologación por IDTERCERO (no NIT suelto).
- Por línea (COD_EXT del XML), no solo cabecera.
- No duplicar KMCOM; homologación = mapeo código proveedor → defaults.
- No cambiar reglas CONTABILIZAR_FCXP ni MCP.
- CUECREDITO obligatoria antes de REGISTRAR.

5. Criterios

1. Camino feliz ≤3 API (ARCHIVOS + REGISTRAR [+ RECONSTRUIR]).
2. Sin cambio obligatorio de pestaña.
3. Segunda factura mismo IDTERCERO + COD_EXT precarga CC/cuenta/servicio.
4. TER sin CUENTA → sistema pide CUECREDITO antes de registrar.
5. FRADIAN.REGISTRADA_CXP=1; FCXP con NOREFERENCIA correcta.
6. Homologación persistida al confirmar líneas nuevas.
7. CONCILIAR_CXP_FRADIAN sin regresión.
8. Factura 20+ líneas sin bucle CRUD_FCXPD.

6. Recomendación

Entregar al desarrollador el paquete único: modelo-entrega-desarrollador.html + mockups + diagrama + SPQ_FCXP.sql de referencia. Prioridad media en plan transversal.
