Alcance acordado: homologación por IDTERCERO + COD_EXT (línea); cabecera CUECREDITO desde TER.CUENTA y captura si falta; flujo rápido REGISTRAR_CXP_FRADIAN sin cambio de pestaña.

1. Flujo usuario (camino feliz)

1 Grilla Radian→ 2 Confirmar→ 3 ARCHIVOS + parse XML→ 4 VALIDA_TERCERO→ 5 Preview cabecera (CUECREDITO)→ 6 CC/cuenta líneas + homologación→ 7 REGISTRAR_CXP_FRADIAN→ 8 [opc] RECONSTRUIR
  1. Usuario pulsa Generar CxP en tab Facturas Radian (sin ir al tab CxP).
  2. FRADIAN.ARCHIVOS → extraerDatosCxpDesdeXml arma dataFCXP + detalleFCXPD[] (cada línea trae COD_EXT del XML).
  3. VALIDA_TERCERO por NIT → obtiene IDTERCERO y TER.CUENTA.
  4. Cabecera: precargar CUECREDITO = TER.CUENTA. Si vacía → campo obligatorio en preview (selector CUE tipo Detalle) antes de continuar.
  5. Líneas: por cada ítem, buscar homologación (IDTERCERO, COD_EXT). Si existe → precargar IDSERVICIO, CCOSTO, CUENTA_SER. Si no → usuario completa en modal; al confirmar → upsert homologación.
  6. POST único REGISTRAR_CXP_FRADIAN con JSON completo (incluye CUECREDITO en cabecera).
  7. Si CXP_KMCOM_AUTOMATICO=SI y alguna línea sin CUENTA_SER → RECONSTRUIR_CUENTAS_FCXPD.

2. Cabecera — CUECREDITO (TER)

OrigenRegla
TER.CUENTAPrimera opción al validar tercero (igual que abrirCxpDesdeRadian hoy).
Preview editableSi TER.CUENTA vacía o inválida en CUE → usuario elige cuenta crédito antes de procesar.
Persistencia terceroOpción recomendada: checkbox «Guardar en tercero» → UPDATE TER SET CUENTA=@CUECREDITO (permiso existente de terceros).
JSON dataFCXPIncluir CUECREDITO explícito en el POST.
SP REGISTRAR_CXP_FRADIANHoy inserta solo TER.CUENTA ignorando JSON. Cambiar: COALESCE(dataFCXP.CUECREDITO, TER.CUENTA) y KO si sigue vacío o no existe en CUE.

3. Homologación por línea — tabla nueva

No duplica KMCOM (matriz servicio+CC→cuenta). Guarda mapeo código ítem proveedor → defaults para Radian.

3.1 DDL propuesto — CXP_RADIAN_HOMO

CREATE TABLE dbo.CXP_RADIAN_HOMO (
    COMPANIA        VARCHAR(2)   NOT NULL DEFAULT '01',
    IDTERCERO       VARCHAR(20)  NOT NULL,
    COD_EXT         VARCHAR(50)  NOT NULL,   -- StandardItemIdentification del XML
    IDSERVICIO      VARCHAR(20)  NOT NULL,   -- FK lógica → SER.IDSERVICIO
    CCOSTO          VARCHAR(20)  NULL,
    CUENTA_SER      VARCHAR(20)  NULL,       -- opcional; KMCOM puede completar
    DESC_EXT        VARCHAR(255) NULL,       -- descripción XML (referencia)
    USUARIO         VARCHAR(12)  NULL,
    FECHA           DATETIME     NULL DEFAULT GETDATE(),
    CONSTRAINT PK_CXP_RADIAN_HOMO PRIMARY KEY (COMPANIA, IDTERCERO, COD_EXT)
);
-- Índice auxiliar por tercero para listados en modal
CREATE INDEX IX_CXP_RADIAN_HOMO_TER ON dbo.CXP_RADIAN_HOMO (IDTERCERO);

3.2 METODOs SPQ_FCXP (nuevos)

METODOEntradaSalida / efecto
BUSCAR_HOMOLOGA_RADIANIDTERCERO, JSON array [{COD_EXT},…]Filas encontradas para precargar modal
GUARDAR_HOMOLOGA_RADIANIDTERCERO, JSON array líneas con COD_EXT, IDSERVICIO, CCOSTO, CUENTA_SER, DESC_EXTMERGE upsert en CXP_RADIAN_HOMO

3.3 Relación con KMCOM

  • Si homologación trae CUENTA_SER → usarla.
  • Si no, y CXP_KMCOM_AUTOMATICO=SI → VAL_CONTABLE / RECONSTRUIR_CUENTAS_FCXPD con IDSERVICIO real (SER) + CCOSTO.
  • KMCOM/KMCOMS siguen siendo la fuente autoritativa de reglas contables por prefijo/área/CC.

6. Cambios SQL obligatorios (resumen)

  1. DDL CXP_RADIAN_HOMO.
  2. SPQ_FCXP: BUSCAR_HOMOLOGA_RADIAN, GUARDAR_HOMOLOGA_RADIAN.
  3. SPQ_FCXP.REGISTRAR_CXP_FRADIAN: leer CUECREDITO del JSON; validar; KO si vacío; usar en INSERT FCXP.
  4. Documentar tabla en qrystalos.documentacion (pendiente BA post-desarrollo).

7. Criterios de aceptación (comité)

  1. Camino feliz ≤3 API (ARCHIVOS + REGISTRAR [+ RECONSTRUIR]).
  2. Sin cambio obligatorio de pestaña.
  3. Segunda factura mismo proveedor + mismo COD_EXT precarga CC/cuenta/servicio desde homologación.
  4. Tercero sin TER.CUENTA → sistema pide CUECREDITO antes de registrar.
  5. FRADIAN.REGISTRADA_CXP=1; FCXP con NOREFERENCIA = documento Radian.
  6. Conciliación masiva CONCILIAR_CXP_FRADIAN sin regresión.

8. Pruebas desarrollador

  • Proveedor con TER.CUENTA poblada → cabecera precargada.
  • Proveedor sin cuenta → bloqueo hasta elegir CUECREDITO válida.
  • Primera factura ítem nuevo → modal manual → homologación guardada.
  • Segunda factura mismo ítem → precarga homologada.
  • Factura 20+ líneas → una sola llamada REGISTRAR (sin timeout bucle).
  • KMCOM automático ON → líneas sin CUENTA_SER en homologación se completan con RECONSTRUIR.
