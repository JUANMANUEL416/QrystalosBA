1. Requerimiento del cliente

En la facturación de insumos No PBS (pañales) el pagador exige el código de servicio agrupador INS0039-2. En Facturación Masiva el detalle de la autorización muestra INS0040, y con ese código no se puede facturar lo que pide la EPS. Hace falta corregir el Id. Servicio desde el sistema. Cómo opera hoy: en Administrativo → Facturación Masiva → Autorizador de medicamentos, la columna Id. Servicio del detalle muestra el código guardado en la línea de autorización. Si la línea quedó con el servicio detalle (INS0040), la factura y los RIPS salen con INS0040. Qué se espera: en el autorizador No PBS, cambiar el Id. Servicio de una línea aún sin facturar al código que exige el pagador (agrupador, p. ej. INS0039-2), con validación de catálogo y tarifa; después de guardar, detalle, factura y RIPS con ese código. Restricción explícita del comité: el script de líneas ya cargadas lo ejecuta soporte por aparte; este desarrollo es mantenimiento en pantalla con confirmación del usuario.

2. Análisis del coordinador

Paso 0 — clasificación: hueco funcional (no capacitación). No existe camino en pantalla para corregir AUTD.IDSERVICIO antes de facturar. Control objetivo: Facturación Masiva → Autorizador de medicamentos → Evento por autorizaciones (permiso FACT_MASIVA_AUT_MED). Filtro tipo medicamento No PBS (USVGS PREF_MED_NOPOS). Caminos actuales en ese control (sin editar servicio): marcar autorizaciones PBS; Facturar No PBS por fila; cambiar POS/No POS; cambiar tercero/plan y recalcular; reliquidar; imprimir factura. El detalle AUTD (Id. Servicio) es solo lectura. Origen del código: muchas autorizaciones se crean desde aplicaciones No POS (GEN_AUT_NOPOS_APLIMF en IXONLINE/SQL SPQ_FTR_MASIVA_COL): INSERT AUTD toma IDSERVICIO desde APLIMF (servicio detalle del insumo). No hay sustitución automática por agrupador de contrato. Al facturar, IXONLINE/SQL SPK_FACTURACE_N (vía FACTURA_AUT_NOPBS en SPQ_FTR_AUT_DISP_COL) clona AUTD.IDSERVICIO a FTRD; RIPS hereda ese código. Caso referencia CEM: INS0040 en detalle vs INS0039-2 exigido por EPS — en catálogo SER son servicios distintos. Handoff Conocimiento pendiente (no bloquea implementación acordada): documentar SPQ_FTR_AUT_DISP_COL en base de procesos (ho-20261016-req-0100016773-ftr-aut-disp).

Criterios de aceptación

  1. Autorización No PBS sin facturar: permite cambiar Id. Servicio al código agrupador; el detalle lo muestra antes de facturar.
  2. Rechaza código inexistente, inactivo o sin tarifa para tercero/plan de la línea.
  3. Línea o autorización ya facturada: la acción no modifica datos.
  4. Tras corregir y facturar (FACTURA_AUT_NOPBS), FTRD lleva el código nuevo.
  5. Si el origen APLIMF sigue con servicio detalle, el usuario ve el código en autorizador y puede corregirlo antes de facturar.

Alcance y restricciones

Alcance: Líneas AUTD No PBS no facturadas en Facturación Masiva → Autorizador de medicamentos; validación SER + tarifa plan.

Fuera: Script masivo de datos ya cargados; facturas emitidas (nota/anulación); sustitución automática silenciosa de todos los servicios por agrupador.

Restricciones: Confirmación explícita del usuario; otros prefijos/planes solo si pasan la misma validación No PBS.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy: En Facturación Masiva → Autorizador de medicamentos, el Id. Servicio del detalle es el que quedó al crear la autorización (a menudo el código del insumo, p. ej. INS0040). Si la EPS pide el agrupador (INS0039-2), soporte debe corregir fuera del sistema. Propuesta: En el mismo autorizador, con filtro No PBS, el usuario podrá cambiar el Id. Servicio de cada línea que aún no esté facturada. El sistema validará que el código exista, esté activo y tenga tarifa para el plan; después de guardar, al facturar saldrán factura y RIPS con ese código.

5.2 Detalle técnico — SQL Server

Objetos: IXONLINE/SQL SPQ_FTR_AUT_DISP_COL (METODO nuevo). Referencia: SPQ_FTR_MASIVA_COL · GEN_AUT_NOPOS_APLIMF (origen IDSERVICIO), SPK_FACTURACE_N (factura desde AUTD). SPK_FACTURACE_N no requiere cambio si AUTD está corregido antes de FACTURA_AUT_NOPBS.

Tablas: AUT, AUTD, SER (validación); posible lectura USVGS PREF_MED_NOPOS.

5.2.1 Fragmentos SQL (especificación)

Especificación para desarrollo en IXONLINE/SQL. No ejecutar desde Qrystalos BA.

-- SPQ_FTR_AUT_DISP_COL · METODO CAMBIAR_IDSERVICIO_AUTD (propuesto)
-- PARAMETROS JSON: IDAUT, NO_ITEM, IDSERVICIO_NUEVO

-- Validaciones (alineadas a FACTURA_AUT_NOPBS / RELIQUIDAR):
--   AUT existe, ESTADO <> Anulada, COALESCE(AUT.FACTURADA,0) <> 1
--   AUTD existe, COALESCE(AUTD.FACTURADA,0) <> 1
--   SER: activo, POS=0, PREFIJO = PREF_MED_NOPOS
--   FNK_VALORSERVICIO(IDTERCEROCA, IDPLAN, IDSERVICIO_NUEVO, ...) > 0
--   IDSERVICIO_NUEVO <> IDSERVICIO actual

UPDATE AUTD
   SET IDSERVICIO = @IDSERVICIO_NUEVO,
       VALOR = @VLR_UNIT,
       VALOREXCEDENTE = @VLR_UNIT * CANTIDAD
 WHERE IDAUT = @IDAUT AND NO_ITEM = @NO_ITEM
   AND COALESCE(FACTURADA,0) <> 1;

EXEC SPK_COPAGO_AUT_CEHOSP_RELIQ @IDAUT, 'CE', @SYS_COMPUTERNAME, @COMPANIA, @IDSEDE, @USUARIO;

SELECT 'OK' OK, @IDSERVICIO_NUEVO IDSERVICIO,
       (SELECT VALORTOTAL FROM AUT WHERE IDAUT = @IDAUT) VALORTOTAL;
