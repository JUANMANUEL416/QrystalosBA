1. Requerimiento del cliente

Se requiere proceso de creación de API para registro o transcripción de fórmula y, a su vez, para la dispensación de la misma. Complemento del comité (PEI / acta): implementar en farmacia el ciclo de Preparación Inmediata — revisión QF, PRM, programación de horarios, preparación, envío a inventario/piso y trazabilidad — integrado con el control de administración de dosis, con jornada operativa 07:00 D a 06:59 D+1.

2. Análisis del coordinador

Paso 0 — clasificación: hueco (API externa + stack FAR_PI no documentado en base) y desarrollo en curso en rama COESME650 (PI parcial en FE). No es capacitación pura: el mandato incluye API y cierre del circuito PEI. Controles y caminos inventariados: • Consulta externa — fórmulas: FormulasCEComponent (MODELO CEFM); envío a farmacia y lista de trabajo. • Farmacia CE — Transcripciones / dispensación: /inv/sol_2 (TRANS_CE, FORMEDCE, FORMEDASIS), LISTA_AUT (DISPENSAR, CONFIRMAR), IZSOL (AGREGAR, CONF_MOVIMIENTO). • Hospitalización — control dosis: /inv/horarios_tratamientos (FarControlDosisComponent, FAR_CTRLDOSIS · LISTAR; PRM vía FAR_IF; preparación FAR_PREP). • Preparaciones inmediatas: /inv/preparaciones_inmediatas (FarPrepInmediatasComponent, FAR_PI). Causa raíz: la KB documenta dispensación (IZSOL) y satélites FAR_IF / FAR_CTRLDOSIS; faltan fichas SPQ_FAR_PI, SPQ_FAR_PREP y SPQ_CEFM. No existe capa API pública reutilizable para terceros. Métodos documentados del formulario cubren el tramo dispensación + PRM; para PI y API hace falta releer PREVERSION (SPQ_FAR_PI, SPQ_FAR_PREP, SPQ_CEFM) — handoffs Conocimiento pendientes.

Criterios de aceptación

  1. API documentada (contrato, autenticación, idempotencia, códigos de error) para registrar/transcribir fórmula CE y consultar estado hasta dispensación, reutilizando reglas de CEFM → AUT/LISTA_AUT → IZSOL.
  2. Ciclo PI según PEI: jornada 07:00–06:59, revisión QF, PRM (FAR_IF), horarios sin pantallas de enfermería, preparación (FAR_PREP), envío a inventario/dispensación, bitácora FAR_PI_EVENTO.
  3. Integración en FarControlDosisComponent y FarPrepInmediatasComponent con permisos USGRUH.
  4. Dispensación final vía IZSOL confirmada (SPK_CONFIRMASAL_CM) sin duplicar salidas.
  5. Pruebas: API happy path, concurrencia MARCAR_OK, jornada cerrada solo lectura, bloqueos PRM (suspendido / PROA), regresión Transcripciones CE manual.

Alcance y restricciones

Alcance: Endpoints API (qrystalos.server), SPQ_FAR_PI / SPQ_FAR_PREP / tablas FAR_PI_*, FE rama COESME650, enlace PI → IZSOL.

Fuera: Contabilidad MCUE/CON, compras, DIAN/RIPS, capacitación solo-UI si el comité mantiene API.

Restricciones: No tablas INTERVENCIONES/INTERD; UNIQUE jornada (sede + fecha operativa); acta PDF sin extracto automático — PEI en imagen de referencia.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy la fórmula de consulta externa se registra en pantalla y la farmacia dispensa por el flujo habitual; la preparación inmediata de medicamentos en hospitalización está a medias en la rama del comité. Se propone terminar el circuito de farmacia (jornada, revisión químico, intervenciones, preparación y envío al piso) y abrir una API segura para que sistemas externos puedan registrar fórmulas y consultar dispensación con las mismas reglas que un usuario en Qrystalos.

  • Rutas: /inv/preparaciones_inmediatas (FarPrepInmediatasComponent), /inv/horarios_tratamientos (FarControlDosisComponent), /inv/sol_2 (Transcripciones CE), consulta externa FormulasCEComponent.
  • Completar PI: flujo PEI en control dosis (lotes/etiquetas/envío según acta), jornada y solo lectura histórica; diálogos FarPrepEnvioDialog, FarIfCrearDialog, FarPiEventosDialog.
  • Permisos: USGRUH por pantalla (Preparaciones inmediatas, Horarios de tratamientos).
  • Mockup: ventana propuesta registrada en el caso (Preparaciones inmediatas / PI), no captura del problema.

6. Qué tener en cuenta

  • Handoffs Conocimiento pendientes: SPQ_FAR_PI, SPQ_FAR_PREP, SPQ_CEFM — documentar antes de implementación final.
  • Releer PREVERSION de SPQ_FAR_PI al implementar; el FE ya asume métodos no fichados en KB.
  • Confirmar alcance API: solo CE, solo PI, o ambos, y consumidor (EPS, middleware, tótem).
  • Regresión: Transcripciones CE manual, LISTA_AUT CONFIRMAR, medicamento suspendido en dispensación (2.0.5+).

Pruebas — desarrollador

  • Lint y permisos USGRUH en pantallas PI y control dosis.
  • PREVERSION: MARCAR_OK concurrente, jornada cerrada, FAR_PREP solo última del usuario.
  • API: contrato, errores KO de SPQ_CEFM/IZSOL propagados sin filtrar datos sensibles.

Pruebas — coordinador (usuario)

  • Happy path PEI vs acta; contraste jornada 07:00–06:59.
  • API registro fórmula + consulta estado hasta dispensación en ambiente test.

Pruebas — soporte

  • Runbook: diferenciar fallo API vs fallo farmacia (copago CE, vigencia IZSOL).
  • Rollback: desactivar endpoints sin borrar FAR_PI histórico.
