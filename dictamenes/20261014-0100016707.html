1. Requerimiento del cliente

Al confirmar una dispensación, aunque la fecha de dispensación de la fórmula reemplace el reloj, el sistema debe comprobar que el periodo contable de esa fecha está abierto y que el inventario de ese periodo también está abierto. Si alguno está cerrado, no debe confirmar.

2. Análisis del coordinador

Clasificación: defecto (no capacitación). El REQ pide bloquear confirmación cuando la fecha efectiva cae en periodo contable o de inventario cerrado; la captura y el diagrama SR20261013-001 apuntan al mismo control que el texto. Paso 0 — ¿Ya existe? No. El control «Periodo inventario / contable abierto» en inventario documenta que CRUD_IMOV y CRUD_IMOV_SAL validan PRI al crear/editar cabecera, pero CONF_MOVIMIENTO, SPK_CONFIRMASAL_CM, SPK_CONFIRMARSALIDAS y CONFIRMA_* figuran explícitamente en noValida PRI / CERRADO_INV. Con CEFM_FECHA_TRANS=SI, SPK_CONFIRMASAL_CM sustituye @HOY por FNK_CEFM_FECHATRANSCRIPCION(@CNSIZSOL) antes de confirmar, de modo que la operación puede caer en un mes distinto al calendario sin pasar por las validaciones de CRUD. Caminos del control inventariados: (A) /inv/sol_2 → Dispensar → Entregar → Procesar → Conf. Mov. → AppStore.json IZSOL · CONF_MOVIMIENTO; (B) Lista de trabajo → CONFIRMAR → SPK_CONFIRMASAL_CM; (C) /inv/ges confirmación de salida manual — fuera de alcance de este REQ. Causa según base de procesos + IXONLINE/SQL SPK_CONFIRMASAL_CM: falta bloqueo PRI entre la resolución de la fecha efectiva (FNK_CEFM_FECHATRANSCRIPCION) y el UPDATE que confirma IMOV.

Criterios de aceptación

  1. Con CEFM_FECHA_TRANS activa, al pulsar Conf. Mov. (o Confirmar en lista de trabajo CE), el sistema usa el año y mes de la fecha efectiva de confirmación (fecha de dispensación de la fórmula cuando FNK_CEFM_FECHATRANSCRIPCION devuelve valor; si no, la fecha del movimiento).
  2. Si no existe fila en PRI para ese año/mes, o PRI.CERRADO=1 (periodo contable cerrado), o PRI.CERRADO_INV=1 (inventario cerrado), la confirmación se aborta sin cambiar existencias ni IMOV.ESTADO.
  3. El mensaje al usuario identifica el conflicto (periodo inexistente o cerrado) con año y mes.
  4. Con ambos cierres abiertos en PRI para ese año/mes, el flujo actual de dispensación confirma igual que hoy.
  5. No regresión en solicitudes sin fórmula transcrita (FNK devuelve NULL).

Alcance y restricciones

Alcance: confirmación de salida de dispensación vía SPQ_IZSOL · CONF_MOVIMIENTO (pantalla Solicitudes /inv/sol_2, control Conf. Mov.) y SPQ_LISTA_AUT · CONFIRMAR (lista de trabajo CE). La validación en SPK_CONFIRMASAL_CM después de resolver la fecha efectiva y antes de descontar existencias.

Excluye: salidas por SPK_CONFIRMARSALIDAS (movimientos manuales /inv/ges), entradas CONF_ENTRADA, anulaciones y cierre de periodos en SPQ_PRI · CRUDPRI (salvo reutilizar criterio de mensaje).

Restricciones: rama bugfix/COESME644; reutilizar texto KO de CRUD_IMOV/CRUD_IMOV_SAL cuando aplique cierre; no cambiar FNK_CEFM_FECHATRANSCRIPCION ni FECHACONF; una consulta PRI por confirmación; validar en PREVERSION.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy farmacia puede confirmar una dispensación aunque la fecha de la fórmula (o la del movimiento) caiga en un mes ya cerrado en contabilidad o en inventario. Se propone que, justo antes de confirmar la salida, el sistema mire el año y mes de esa fecha y, si el periodo no existe o está cerrado en cualquiera de los dos sentidos, muestre un aviso y no complete la confirmación.

5.1 Detalle técnico — Frontend (Qrystalos2)

  • Impacto parcial: no es obligatorio cambiar pantallas si el backend devuelve el RAISERROR y el FE ya muestra errores de AppStore.json.
  • Opcional: en IMOVComponent / flujo lista de trabajo, asegurar que el mensaje de periodo cerrado o inexistente se muestre completo (año/mes) sin truncar.
  • Mockup UX: ventana propuesta con diálogo de rechazo por periodo cerrado (registrada para correo y validación visual; no es la captura del defecto).
  • Permisos: sin cambio en USGRUH del control Conf. Mov.

5.2.1 Fragmentos SQL (especificación)

Especificación para desarrollo. No ejecutar desde Qrystalos BA.

-- Objeto: SPK_CONFIRMASAL_CM (IXONLINE/SQL PREVERSION)
-- Ubicación: inmediatamente después de IF @FECHATRANS_CEFM IS NOT NULL SET @HOY = @FECHATRANS_CEFM
-- y ANTES del primer UPDATE a IMOVH / descuento de existencias.

DECLARE @ANO_PRI INT = YEAR(@HOY), @MES_PRI INT = MONTH(@HOY)
-- Usar la misma @COMPANIA que el bloque contable del SP (p. ej. desde CEN/COMPANIA del movimiento).

IF NOT EXISTS (
  SELECT 1 FROM PRI WITH (NOLOCK)
  WHERE COMPANIA = @COMPANIA AND ANO = @ANO_PRI AND MES = @MES_PRI
)
BEGIN
  RAISERROR('No existe periodo contable/inventario para %d/%02d. No se puede confirmar la dispensación.', 16, 1, @ANO_PRI, @MES_PRI)
  RETURN
END

IF EXISTS (
  SELECT 1 FROM PRI WITH (NOLOCK)
  WHERE COMPANIA = @COMPANIA AND ANO = @ANO_PRI AND MES = @MES_PRI
    AND (COALESCE(CERRADO, 0) = 1 OR COALESCE(CERRADO_INV, 0) = 1)
)
BEGIN
  RAISERROR('No se Permiten hacer Movimientos de Periodos Cerrados.', 16, 1)
  RETURN
END

6. Qué tener en cuenta

  • No confundir con confirmación manual en /inv/ges (SPK_CONFIRMARSALIDAS) — fuera de alcance salvo REQ futuro.
  • Variable CEFM_FECHA_TRANS: solo afecta cuándo se reemplaza @HOY; no modificar FNK_CEFM_FECHATRANSCRIPCION en este ticket.
  • Performance: una sola consulta PRI por confirmación (índice habitual COMPANIA+ANO+MES).
  • Documentación pendiente en base: FNK_CEFM_FECHATRANSCRIPCION y SPK_CM_GENIMOV_SOL (handoff Conocimiento).
  • Contabilización posterior (SPK_NC_CONTAB_INV): no cambia cuando el periodo está abierto; este fix evita confirmar en periodo cerrado.
