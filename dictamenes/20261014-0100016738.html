1. Requerimiento del cliente

Declarar la remisión o vaciar el bloque Novedad: 5. GE0058, «longitud N mayor a la máxima (0)». 77 facturas; en el seguimiento 33 facturas y 162 ocurrencias ($347.255.102). Problema: la casilla 64 (tipo de referencia) va vacía y las 65 a 69 van llenas (fecha, hora, código de habilitación de la IPS remitente, profesional y cargo). La malla exige el bloque vacío cuando no hay tipo de referencia. En el seguimiento, una atención genera cinco glosas (CTOB902). Ejemplo: CNOR110, 23 sep 2026.

2. Análisis del coordinador

Paso 0 — clasificación: **defecto** (no capacitación). El control de expediente SOAT y exportación FURIPS ya existen; falla la coherencia entre tipo de referencia (casilla 64) y el resto del bloque de remisión (65–69). REQ vs pantalla: el texto pide «declarar la remisión o vaciar el bloque». En Asistencial → SOAT → pestaña **Remisión**, «Remitido De» captura fecha/hora, IPS remitente, profesional y cargo (columnas HACTRAN que alimentan 65–69), mientras «Tipo Referencia» vive en «Remitido A» (REM_TIPOREFERENCIA → 64). No hay camino que al vaciar el tipo referencia limpie 65–69 ni que el export los suprima. Causa técnica: IXONLINE/SQL · **SPQ_FURIPS** (PREVERSION 2.0.9) proyecta CAMPO64 desde REM_TIPOREFERENCIA pero CAMPO65–69 siempre desde HACTRAN aunque 64 vaya vacío (el SP ya usa @SINCONDUCTOR para conductor, no para remisión). El FE exporta TXT con el recordset y JSON vía useHactranPlanosExport desde el mismo origen. Recomendación: opción B — SPQ_FURIPS (@SINREMISION en CAMPO64–69 en todas las ramas FURIPS/FURIPSCXC) + HactranComponent (normalizar al guardar o al limpiar REM_TIPOREFERENCIA). Saneamiento masivo de 77 casos: operación opcional aparte si Financiero autoriza UPDATE + reexportación FURIPS.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Cuando no hay tipo de referencia de remisión, el sistema debe tratar el bloque FURIPS 64–69 como vacío: al exportar no envía fecha, hora ni datos del remitente, y al guardar el expediente limpia esos campos si el usuario quitó el tipo referencia. Si sí hay tipo referencia, todo sigue igual que hoy.

5.1 Detalle técnico — Frontend (Qrystalos2)

  • HactranComponent.vue — pestaña Remisión: al cambiar o limpiar REM_TIPOREFERENCIA, vaciar FECHA_RD (parte remisión), COD_IPSREMITE, PERSONAREMITE, CARGOPERREMITE y campos temporales tmp.fechaREMI / tmp.horaREMI asociados, antes de armar el JSON de UPDATE.
  • Alternativa equivalente: validación que impida guardar si 64 está vacío y 65–69 tienen datos (mensaje claro «declare tipo referencia o vacíe remisión»). Preferir vaciado automático si el usuario limpió tipo referencia (opción B acordada).
  • useHactranPlanosExport.js — solo si tras el cambio SQL algún remap JSON aún expone campos de remisión; en principio basta el recordset corregido.
  • Mockup UX registrado: ventana propuesta (coherencia tipo referencia / bloque remisión), no captura del error.

5.2 Detalle técnico — SQL Server

  • Objeto: SPQ_FURIPS (IXONLINE/SQL PREVERSION 2.0.9).
  • METODOs: FURIPS y FURIPSCXC.
  • Declarar @SINREMISION junto a @SINCONDUCTOR y aplicar CASE WHEN @SINREMISION = 1 THEN '' en CAMPO64–69 en cada rama del SELECT cabecera.
  • No modificar recordset FURIPS 2 (CAMPO01–09) ni delegación a SPQ_FURIPS_V2.

5.2.1 Fragmentos SQL (especificación)

Especificación para desarrollo; no ejecutar desde Qrystalos BA.

-- Objeto: SPQ_FURIPS (IXONLINE/SQL PREVERSION 2.0.9)
-- AFTER (junto a @SINCONDUCTOR; replicar en cada rama QX/CI/CE y FURIPSCXC):

DECLARE @SINREMISION SMALLINT = CASE
  WHEN NULLIF(LTRIM(RTRIM(COALESCE(A.REM_TIPOREFERENCIA,''))), '') IS NULL THEN 1
  ELSE 0 END;

CAMPO64_TIPOREFERENCIA = CASE WHEN @SINREMISION = 1 THEN '' ELSE COALESCE(A.REM_TIPOREFERENCIA,'') END,
CAMPO65_FECHAREMISION = CASE WHEN @SINREMISION = 1 THEN '' ELSE CASE WHEN COALESCE(FORMAT(A.FECHA_RD,'dd/MM/yyyy'),'01/01/1900')='01/01/1900' THEN '' ELSE COALESCE(FORMAT(A.FECHA_RD,'dd/MM/yyyy'),'') END END,
CAMPO66_HORASALIDA = CASE WHEN @SINREMISION = 1 THEN '' ELSE COALESCE(FORMAT(A.FECHA_RD,N'HH:mm'),'') END,
CAMPO67_CODHABILITACIONREMITENTE = CASE WHEN @SINREMISION = 1 THEN '' ELSE COALESCE(A.COD_IPSREMITE,'') END,
CAMPO68_PROFESIONALREMITE = CASE WHEN @SINREMISION = 1 THEN '' ELSE COALESCE(A.PERSONAREMITE,'') END,
CAMPO69_CARGOPERSONAREMITE = CASE WHEN @SINREMISION = 1 THEN '' ELSE COALESCE(A.CARGOPERREMITE,'') END,

-- Validación (preversión):
SELECT H.CNSHACTRAN, F.N_FACTURA, H.REM_TIPOREFERENCIA, H.FECHA_RD, H.COD_IPSREMITE, H.PERSONAREMITE, H.CARGOPERREMITE
FROM HACTRAN H
INNER JOIN FTR F ON F.CNSHACTRAN = H.CNSHACTRAN
WHERE (H.REM_TIPOREFERENCIA IS NULL OR LTRIM(RTRIM(H.REM_TIPOREFERENCIA)) = '')
  AND (
    NULLIF(LTRIM(RTRIM(COALESCE(H.COD_IPSREMITE,''))), '') IS NOT NULL
    OR NULLIF(LTRIM(RTRIM(COALESCE(H.PERSONAREMITE,''))), '') IS NOT NULL
    OR NULLIF(LTRIM(RTRIM(COALESCE(H.CARGOPERREMITE,''))), '') IS NOT NULL
    OR (H.FECHA_RD IS NOT NULL AND CONVERT(date, H.FECHA_RD) <> '1900-01-01')
  );

-- Saneamiento opcional (cliente, post-fix código):
-- UPDATE H SET FECHA_RD = NULL, COD_IPSREMITE = '', PERSONAREMITE = '', CARGOPERREMITE = ''
-- FROM HACTRAN H WHERE ... mismo filtro ...;
