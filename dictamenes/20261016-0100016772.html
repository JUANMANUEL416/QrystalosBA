1. Requerimiento del cliente

En Inventario → Lista de trabajo se requiere una ventana «Gestión Delivery» para el personal de Operaciones, con el fin de centralizar repartos, asignar motorizados y hacer seguimiento de entregas originadas en Farmacia (tablas IZDOMP e IZDOMPD). Estados de negocio: Pendiente (sin motorizado), Asignado, Entregado, Reprogramado, Rechazado. Ante entrega no realizada por el motorizado, Operaciones debe poder reprogramar (nuevo ciclo de asignación) o rechazar (habilitar devolución en Farmacia). Solicitante: Williams Pizarro. Primera sesión técnica con desarrollo previo en rama CINTER (delivery MAD).

2. Análisis del coordinador

Paso 0 — clasificación: hueco funcional (desarrollo). No es capacitación. REQ vs captura: el REQ pide cola Operaciones; la captura de referencia muestra el control Farmacia «Gestionar Delivery» en Lista de trabajo (programa Delivery MAD), no la bandeja de Operaciones. Caminos actuales inventariados: • Farmacia — Lista de trabajo: botón «Gestionar Delivery» (permiso dispensar_med, filtro Delivery MAD) abre flujo de dispensación + creación de reparto; la UI exige seleccionar RUTA_MOTO al guardar. • Inventario — ruta delivery_mad: mismo flujo orientado a un IDAUT (no lista global Operaciones). • Motorizado — DELIVERY_MAD · LISTAR_ENTREGAS_CONDUCTOR, LISTAR_LINEAS_REPARTO_GEO, REGISTRAR_ESTADO_LINEA_GEO (ENTREGADO / NO_ENTREGADO, firma paciente). • Operaciones — no existe pantalla de lista ni METODOs de asignación / reprogramación / rechazo en IXONLINE/SQL SPQ_DELIVERY_MAD documentado hoy (cinco METODOs). Estados técnicos actuales (SPQ_DELIVERY_MAD · CREAR_REPARTO): cabecera IZDOMP «PROGRAMADO»; líneas IZDOMPD «EN_REPARTO»; cierre geo → ENTREGADO / NO_ENTREGADO / CERRADO_PARCIAL. No coinciden con los cinco estados del REQ. Devolución Farmacia: control «Devolver medicamentos» (LISTA_AUT · PROCESARIDEVD / IDEV) no depende hoy de rechazo Operaciones sobre IZDOMP. Recomendación: extender SPQ_DELIVERY_MAD y nueva página Operaciones; Farmacia solo envía a cola (PENDIENTE, sin IDRUTA).

Criterios de aceptación

  1. Ítem de menú Inventario → Lista de trabajo → «Gestión Delivery» con permiso USGRUH propio (Operaciones), distinto del botón Farmacia «Gestionar Delivery».
  2. Grilla global IZDOMP/IZDOMPD con filtros (fechas, estado, paciente, IDAUT, conductor).
  3. Estados Pendiente, Asignado, Entregado, Reprogramado, Rechazado visibles y auditables.
  4. Asignación / reasignación RUTA_MOTO desde Pendiente o Reprogramado; conductor recibe en lista geo.
  5. Ante NO_ENTREGADO total, Operaciones reprograma o rechaza.

  7. Farmacia no asigna motorizado al enviar a cola.
  8. Regresión: entrega con firma; REVERTIR_DISPENSACION bloqueada si hay IZDOMP activo.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy Farmacia puede dispensar y crear el reparto eligiendo ya al motorizado. Se propone que Farmacia solo deje la solicitud en una cola compartida (IZDOMP) y que Operaciones, desde una nueva lista en Inventario, asigne conductores, haga seguimiento (pendiente → asignado → entregado) y decida reprogramar o rechazar cuando la entrega falla; si rechazan, Farmacia podrá usar el botón de devolución que ya existe.

5.2.1 Fragmentos SQL (especificación)

Especificación para desarrollo en IXONLINE/SQL. No ejecutar desde Qrystalos BA.

-- SPQ_DELIVERY_MAD · CREAR_REPARTO (ajuste)
-- Si IDRUTA IS NULL → IZDOMP.ESTADO = 'PENDIENTE'
-- Si IDRUTA informado → 'ASIGNADO' (convivencia con geo)

-- METODO LISTAR_GESTION_DELIVERY (nuevo) — cola Operaciones
-- Filtros: FECHA_DESDE, FECHA_HASTA, ESTADO_NEGOCIO, BUSCAR

-- METODO ASIGNAR_MOTORIZADO (nuevo)
UPDATE IZDOMP SET IDRUTA = @IDRUTA, ESTADO = 'ASIGNADO', ...
WHERE ID = @ID AND ESTADO IN ('PENDIENTE','REPROGRAMADO');

-- METODO REPROGRAMAR_ENTREGA (nuevo)
-- FECHA_REF, HORAINI/HORAFIN, IDRUTA = NULL, ESTADO = 'REPROGRAMADO'

-- METODO RECHAZAR_ENTREGA (nuevo)
UPDATE IZDOMP SET ESTADO = 'RECHAZADO', OBSERVACION = @MOTIVO WHERE ID = @ID;
UPDATE IZDOMPD SET ESTADO = 'RECHAZADO' WHERE ID_IZDOMP = @ID;

-- REGISTRAR_ESTADO_LINEA_GEO — revisar transición cabecera cuando NO_ENTREGADO → bandeja Ops

-- Validación:
SELECT ID, IDAUT, IDRUTA, ESTADO FROM IZDOMP WHERE IDAUT = @IDAUT;
SELECT ESTADO, COUNT(*) FROM IZDOMPD WHERE ID_IZDOMP = @ID GROUP BY ESTADO;
