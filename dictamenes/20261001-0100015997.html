1. Requerimiento del cliente

Error al registrar CUV en validación externa. El usuario reporta que al intentar registrar el CUV en la validación externa, se presenta un error que impide el registro tanto del CUV como de la respuesta en Krystalos. Pasos: (1) Acceder al módulo de validación externa. (2) Intentar registrar un CUV. (3) Observar el mensaje de error. Contexto: cuando se realiza la validación externa del ministerio, el archivo .txt que genera ese sistema no es compatible con Qrystalos; se debe identificar y ajustar para que el sistema lo tome correctamente.

Criterios de aceptación

1) En Facturación → Envíos y respuestas (Validaciones FEV-RIPS), control «Validación externa»: con los archivos del ministerio/SISPRO (.txt o .json de envío y respuesta) para FEV327665 / CNS 0101223197, al pulsar Registrar no aparece «JSON text is not properly formatted…» y el flujo termina con éxito. 2) Tras registrar, GET_DATOS muestra CUV hex (96 caracteres) en FTR/FTRJSON y JSON_RESPUESTA persistido; paquete FEV-RIPS y radicación posterior disponibles. 3) Respuesta externa solo-CUV o JSON no estándar con CodigoUnicoValidacion identificable → normalizada al contrato SISPRO antes de SET_DATOS. 4) JSON de envío con tokens inválidos para SQL Server (NULL/NaN sin comillas, basura antes del «{») → corregidos o rechazados en FE con mensaje claro. 5) Regresión: «Validar ahora», cola SISPRO y «Subir JSON y Validar» sin cambio; generación RIPS (FTR_COL · RIPS_JSON) intacta.

Alcance y restricciones

Alcance: ValidacionesFEVRipsComponent.vue (Validación externa, guardarValidacionExterna), composable de parseo/normalización de archivos externos; SQL opcional SPQ_RIPS · SET_DATOS si persiste fallo OPENJSON. Proceso rips-json, control enviar-cuv. Fuera de alcance: reglas SISPRO, radicar CXC, DIAN, regeneración masiva RIPS. Restricciones: rama bugfix/CMAICA138; sin contabilidad; contrato MODELO RIPS · SET_DATOS/GET_DATOS; envío con rips + numFactura/numNota coherente (excepción capitada existente); probar con archivos reales del ministerio.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy, cuando el usuario valida en el portal del ministerio y trae los archivos .txt/.json a «Validación externa», Qrystalos no logra interpretar bien ese contenido y el servidor rechaza el guardado; por eso no queda el CUV ni la respuesta en la factura. Se propone enseñar al sistema a «limpiar y entender» esos archivos del ministerio (igual que ya entiende la respuesta directa de SISPRO) y recién ahí guardar el CUV en la factura, sin cambiar el resto del proceso de facturación electrónica en salud.

5.1 Detalle técnico — Frontend (Qrystalos2)

  • Crear composable (p. ej. src/composables/fevrips/useParseJsonFevRipsExterno.js) con: lectura UTF-8 + BOM; extracción del primer objeto JSON balanceado; reemplazo de tokens no JSON estándar (NaN, undefined, NULL sin comillas) por null; detección de respuesta que sea solo CUV hex (96) → construir objeto con ResultState: true y CodigoUnicoValidacion (patrón respuestaSisproDesdeCuvLocal).
  • En guardarValidacionExterna: usar el composable en lugar de parseJsonDesdeTexto directo; mantener validaciones existentes (rips, numFactura/numNota, buscarCodigoUnicoValidacion, capitada).
  • Antes de appStore.json, asegurar que JSON_ENVIO y JSON_RESPUESTA serializan JSON compatible con SQL Server (JSON.stringify sobre objetos ya parseados).
  • Mejorar mensajes $q.notify cuando falle el parseo (indicar token/probable causa ministerio vs UTF-8).
  • Regresión manual: Validar ahora, Subir JSON y Validar, envío masivo (useEnvioMasivo*.js · SET_DATOS).

5.2 Detalle técnico — SQL Server

Objeto IXONLINE/SQL · SPQ_RIPS · METODO SET_DATOS. Cambio opcional si tras sanitización FE aún falla: en la extracción de parámetros, no usar AS JSON en columnas JSON_ENVIO/JSON_RESPUESTA del OPENJSON(@PARAMETROS); validar con ISJSON() y devolver fila ERROR legible antes del bloque TRY genérico. Reglas de negocio (ResultState, ISVALIDACUV, UPDATE FTR/FTRJSON) sin cambio.

6. Qué tener en cuenta

  • CUV validado no implica cuenta radicada (FCXC) — invariante proceso rips-json.
  • Sin muestra de archivos ministerio en el caso, el desarrollador debe solicitar el par envío+respuesta de Maicao para regresión.
  • Tipo IX «Performance»; el análisis es defecto funcional FEV-RIPS.
  • No mezclar con circuito DIAN (FACTE/CUFE) ni JSON Perú.
