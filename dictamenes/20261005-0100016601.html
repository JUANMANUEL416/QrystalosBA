1. Requerimiento del cliente

Las notas débito y crédito electrónicas no generan ni guardan el PDF como sí ocurre con la factura. Sin ese documento el correo automático no tiene qué adjuntar y la nota no sale sola hacia el destinatario. Hoy el PDF solo aparece si alguien imprime la nota o descarga el ZIP. Se necesita que, al quedar notificada, se genere el documento y se envíe por correo sin intervención del usuario.

Criterios de aceptación

1) Notificar una nota débito y una crédito (Colombia, FACTE=2) sin abrir Imprimir Nota: queda el PDF persistido y sale el correo automático con el documento adjunto. 2) Nota de anulación (PROCEDENCIA FACTURA / concepto anulación) y nota parcial: el PDF corresponde al mismo criterio visual que hoy Imprimir Nota (ImprimeFormatoFnot / getPDFNotadbcr ANULA vs PARCIAL en Perú). 3) Reprocesar una nota ya enviada: no duplica fila de PDF ni reenvía correo (idempotencia). 4) Sin correo de destino o fallo SMTP: el PDF queda guardado; el error de envío es consultable para corregir y reintentar (p. ej. reenvío desde Proceso DIAN / log, sin perder el documento). 5) Imprimir Nota y ZIP masivo en Notas DB/CR: mismo resultado que hoy (generación en navegador, descarga local). 6) Pestaña Gen. PDF de Facturación (GENPDF_FACTURAS / FTR_DOCS): no incluye notas ni cambia su conteo por este flujo.

2. Análisis del coordinador

Paso 0 — ¿Ya existe? Clasificación: HUECO DE PROCESO (no capacitación ni defecto puntual). Inventario de caminos en Notas DB/CR (Administrativo → Notas DB/CR): • Imprimir Nota — FNOT_IMPRESION · DATOSFNOT vía ImprimeFormatoFnot / fmtFnot01: PDF solo en navegador. • Impresión masiva ZIP — JSZip en NotasDBCRComponent sobre el mismo render; sin persistencia en BD. • Encolar / Proceso DIAN — FNOT_COL · FNOT_ENCOLAR + servicio facturador → FNOT.FACTE=2: notifica DIAN; no guarda PDF ni encola correo con adjunto de nota. • Gen. PDF (Facturación) — FTRE_COL · GENPDF_FACTURAS + store GenPdfFtre: solo facturas FACTE=2 sin FTR_DOCS; excluye notas (criterio 6). • Reenvío correo documentado en Proceso DIAN — RESET_NOTIFICADOS apunta a FTRE de facturas; no hay binario persistido de nota. Contraste con facturas: ImprimeFormatoFtr con factura notificada invoca FTR_COL · ADD_PDF_FTR (insert FTR_DOCS si no existe). ImprimeFormatoFnot no tiene equivalente GET/ADD base64. Causa: ausencia de tabla/cola de PDF de nota y de paso en el pipeline de correo FE que adjunte ese binario para TIPODOC NOTACR/NOTADB. Recomendación: extensión simétrica a facturas con cola separada (GENPDF_NOTAS), job en servidor alineado opcionalmente con REQ 0100016602 (PDF facturas), reutilizando la misma lógica visual de impresión. Perú SUNAT fuera de alcance salvo extensión de comité.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy la nota electrónica puede quedar bien ante la DIAN, pero el PDF solo existe si alguien imprime o baja un ZIP; por eso el correo automático no tiene adjunto. Se propone que, al quedar la nota notificada, un proceso del servidor genere el mismo PDF que vería el usuario al imprimir, lo guarde asociado a la nota y dispare el correo al destinatario, sin abrir Facturación ni Notas DB/CR. Si el correo falla, el PDF queda guardado para reintentar. Imprimir y el ZIP masivo siguen igual; la cola de PDF de facturas no incluye notas.

-- Referencia patrón: IXONLINE/SQL · SPQ_FTR_COL · ADD_PDF_FTR (insert FTR_DOCS si FACTE=2 y NOT EXISTS)

-- Especificación 1: tabla de persistencia (nombre a confirmar en PREVERSION)
CREATE TABLE dbo.FNOT_DOCS (
  CNSFNOT VARCHAR(20) NOT NULL,
  CLASE   CHAR(1) NOT NULL,
  DOCBASE64 NVARCHAR(MAX) NOT NULL,
  FECHA_REG DATETIME DEFAULT GETDATE(),
  CONSTRAINT PK_FNOT_DOCS PRIMARY KEY (CNSFNOT, CLASE)
);

-- Especificación 2: SPQ_FNOT_IMPRESION (o SPQ_FNOT_COL) · ADD_PDF_FNOT
IF @METODO = 'ADD_PDF_FNOT'
BEGIN
  SELECT @CNSFNOT = JSON_VALUE(@PARAMETROS,'$.CNSFNOT'),
         @CLASE   = JSON_VALUE(@PARAMETROS,'$.CLASE');
  SELECT @DOCBASE64 = DOCBASE64 FROM OPENJSON(@PARAMETROS) WITH (DOCBASE64 NVARCHAR(MAX) '$.DOCBASE64');
  IF NOT EXISTS (SELECT 1 FROM FNOT WHERE CNSFNOT=@CNSFNOT AND CLASE=@CLASE AND COALESCE(FACTE,0)=2 AND ESTADO<>'A')
     RAISERROR('Nota no notificada o anulada',16,1);
  INSERT INTO FNOT_DOCS (CNSFNOT, CLASE, DOCBASE64)
  SELECT @CNSFNOT, @CLASE, @DOCBASE64
  WHERE NOT EXISTS (SELECT 1 FROM FNOT_DOCS WHERE CNSFNOT=@CNSFNOT AND CLASE=@CLASE);
  SELECT 'OK' OK;
END
