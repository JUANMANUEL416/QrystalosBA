1. Requerimiento del cliente

Se requiere realizar un ajuste en el módulo de Glosas, específicamente en la funcionalidad de Devolución, de manera que el sistema permita registrar una observación individual para cada factura que se desee devolver al área de Cartera. Actualmente, al realizar la devolución de varias facturas, se requiere contar con la posibilidad de especificar de manera independiente el motivo u observación correspondiente a cada una de ellas. Contexto operativo: al devolver de auditoría a cartera el sistema asocia impresión o glosa sin pedir observaciones. Se pide captura individual al elegir la glosa, edición en tabla detalle, plantilla Excel para carga masiva y variable de sistema (solo este proyecto) que, si está activa, obligue observaciones de mínimo 20 caracteres antes de cerrar el envío.

Criterios de aceptación

1) En Auditoría → Glosas → pestaña Devolver (DevolResGloComponent), cada ítem ENTD del envío abierto muestra la observación de devolución y permite editarla mientras ENT.CERRADO=0 y ENT.ESTADO≠recibido/anulado. 2) Al agregar una glosa de forma individual (catálogo «Elegir Glosa»), si la variable USVGS del proyecto está activa, el sistema solicita observación (mín. 20 caracteres) antes de confirmar ENT_ADDRESPGLO; si está inactiva, el comportamiento actual se mantiene. 3) Con entrega abierta y al menos un ítem en detalle, existe acción «Descargar plantilla» y carga masiva que actualiza ENTD.OBSERVACION por CNSGLO. 4) Si la variable USVGS está activa, «Cerrar envío» (ENT_CIERRARPTAGLOSA) rechaza el cierre cuando falte observación válida en algún ítem. 5) Cartera en Recep. respuestas (RecepRtasGComponent) visualiza la observación por factura (solo lectura). 6) Sin variable activa: regresión cero en otros clientes.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy, al devolver respuestas de glosa a cartera, el sistema solo agrega las facturas al paquete (por impresión o una a una) con un texto genérico y cierra el envío sin pedir el motivo por factura. Se propone que auditoría pueda escribir (o cargar en Excel) una observación distinta para cada factura, guardada en el detalle de la entrega; en Medical, con un interruptor de configuración, esas observaciones serán obligatorias (mínimo 20 caracteres) antes de cerrar el envío, y cartera las verá al recibir.

5.1 Detalle técnico — Frontend (Qrystalos2)

  • DevolResGloComponent.vue — En dtEntdG: columna OBSERVACION; botón Editar (evento genérico) → diálogo → ENTD_ACTUALIZA_OBSERV. Tras ElegirRespuesta individual: si USVGS activa, pedir observación antes de ENT_ADDRESPGLO con PARAMETROS.OBSERVACION.
  • Botones «Descargar plantilla» / «Cargar observaciones» en zona de detalle ENTD (entrega abierta, patrón RespGlosasComponent + XLSX).
  • Bloqueo UI al «Cerrar envío» si variable activa y filas sin observación válida (refuerzo del KO de ENT_CIERRARPTAGLOSA).
  • RecepRtasGComponent.vue — Añadir observación de devolución en grilla ENTD (solo lectura).
  • Permisos existentes: GLOSAS_DEVOLVER / GLOSAS_AUDITORIA. Rama feature/MDICAL806.

5.2 Detalle técnico — SQL Server

Objeto: SPQ_FGLO_COL. Releer PREVERSION al implementar (referencia sql_refe/0100016259). Alcance: extender ENT_ADDRESPGLO y ENT_CIERRARPTAGLOSA; crear ENTD_ACTUALIZA_OBSERV, PLANTILLA_OBS_DEVOL_GLOSA, CARGA_MASIVA_OBS_DEVOL_GLOSA. Validación USVGS vía FNK_VALORVARIABLE. Sin nuevas tablas.

5.2.1 Fragmentos SQL (especificación)

Especificación para desarrollo — no ejecutar desde Qrystalos BA.

-- ENT_ADDRESPGLO: OPENJSON + OBSERVACION VARCHAR(2024) '$.OBSERVACION'
-- INSERT ENTD: COALESCE(NULLIF(LTRIM(RTRIM(@OBSERVACION)),''), 'Enviado desde Respuestas Quasar')

-- ENT_CIERRARPTAGLOSA (si USVGS activa):
IF DBO.FNK_VALORVARIABLE('IDOBS_OBLIG_DEVOL_GLOSA') IN ('1','SI','S')
  AND EXISTS (SELECT 1 FROM ENTD WHERE CNSENTREGA=@CNSENTREGA AND PROCESO='GLOSAS'
    AND (OBSERVACION IS NULL OR LEN(LTRIM(RTRIM(OBSERVACION)))<20
         OR OBSERVACION='Enviado desde Respuestas Quasar'))
  SELECT 'KO' OK, 'Debe registrar observación de devolución (mín. 20 caracteres) en todas las glosas del envío.' ERROR

-- ENTD_ACTUALIZA_OBSERV: UPDATE ENTD SET OBSERVACION=@OBS WHERE CNSENTREGA + NODOCUMENTO + ENT abierto

-- Validación:
SELECT ENTD.NODOCUMENTO, ENTD.OBSERVACION, FGLO.N_FACTURA
FROM ENTD INNER JOIN FGLO ON ENTD.NODOCUMENTO=FGLO.CNSGLO
WHERE ENTD.CNSENTREGA=@CNSENTREGA AND ENTD.PROCESO='GLOSAS';

6. Qué tener en cuenta

  • No confundir con recaudo INGRESO=GLOSAS ni con códigos FCGLO CLASE=Devolucion.
  • Texto legado «Enviado desde Respuestas Quasar» debe tratarse como observación inválida cuando USVGS exige motivo real.
  • Carga masiva solo actualiza ítems ya en el ENT abierto del usuario (no crear ENTD nuevos por Excel).
  • EXPORTA_RPTAGLOSAS hoy no exporta OBSERVACION — opcional incluirla en mejora posterior.
  • Confirmar ID definitivo de variable USVGS antes de merge a calidad.
  • Alta USVGS solo en base Medical; otros clientes sin variable = comportamiento actual.

Restricciones (alcance acotado)
