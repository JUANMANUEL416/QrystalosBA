1. Requerimiento del cliente

En el módulo Log-Facturación el cliente necesita descargar un Excel para validar fechas de notificación. El archivo sí se genera al pulsar el botón Excel, pero llega sin la extensión .xlsx; Windows no lo reconoce como libro de Excel y obliga a renombrarlo manualmente (palitivo que indicó soporte). Se solicita que, al descargar por el botón Excel, el archivo traiga automáticamente la extensión .xlsx para facilitar la validación de fechas de notificación.

2. Análisis del coordinador

Clasificación: defecto (no capacitación ni hueco funcional). Proceso dian-xml · control Log Facturas (correo): pestaña «Log de notificaciones por correo (FTRE)», ruta /admin/facturacion, permiso TAB_SEND_FTR, componente LOGFacturas.vue. Caminos del control inventariados: (1) Filtrar la grilla FTRE y pulsar Excel → exportación vía AppStore.read (tabla FTRE, página completa) y writeFile en el navegador. Este es el camino del REQ. (2) Reenviar (fila) y Reenviar Filtrados → FTR_COL · RESET_NOTIFICADOS / RESET_NOTIFICADOS_MASIVO. Fuera del arreglo; deben quedar iguales. (3) Reset Filtros y demás columnas de la grilla → sin cambio. El texto «no me descarga» del ticket describe la percepción del usuario (no puede abrir el archivo); la captura confirma descarga exitosa con nombre Log_Notificaciones_FTRE_AAAAMMDD sin extensión. Causa: el computed nombreExcelExport arma Log_Notificaciones_FTRE_ + fecha sin .xlsx. ServerSideTableComponent.exportarExcel solo aplica Descarga.xlsx cuando el nombre viene vacío; si viene informado, xlsx.writeFile usa el literal y el SO no asocia tipo MIME. No interviene IXONLINE/SQL en la exportación Excel. Los METODO de reenvío (RESET_NOTIFICADOS) no aplican a este fix.

  1. En Administrativo → Facturación → pestaña Log Facturas, con la grilla «Log de notificaciones por correo (FTRE)» y filtros que devuelvan filas, el botón Excel descarga un archivo cuyo nombre termina en .xlsx (ejemplo: Log_Notificaciones_FTRE_20261019.xlsx).

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy, en Log Facturas, el botón Excel descarga el log de notificaciones, pero el archivo llega sin la extensión .xlsx y Windows no lo abre. Hay que renombrarlo a mano para revisar las fechas de notificación. El mismo botón debe dejar el archivo listo para abrir, con .xlsx en el nombre.

5.1 Detalle técnico — Frontend (Qrystalos2)

LOGFacturas.vue — Ajustar el computed nombreExcelExport para que el valor devuelto termine en .xlsx (por ejemplo Log_Notificaciones_FTRE_${YYYYMMDD}.xlsx).

ServerSideTableComponent.vue — En exportarExcel, antes de xlsx.writeFile, calcular el nombre final:

  • Si nombreExcel está vacío → mantener Descarga.xlsx (comportamiento actual).
  • Si no termina en .xlsx ni .xls (comparación case-insensitive) → concatenar .xlsx una vez.
  • En caso contrario → usar el nombre tal cual.

Especificación ilustrativa (no ejecutar desde BA):

// LOGFacturas.vue — nombreExcelExport
return `Log_Notificaciones_FTRE_${hoy}.xlsx`;

// ServerSideTableComponent.vue — exportarExcel (antes de writeFile)
let fileName = props.nombreExcel === '' ? 'Descarga.xlsx' : props.nombreExcel;
const lower = fileName.toLowerCase();
if (!lower.endsWith('.xlsx') && !lower.endsWith('.xls')) {
  fileName = `${fileName}.xlsx`;
}
xlsx.writeFile(workbook, fileName);

Riesgo de regresión: bajo en Log Facturas; revisar que otras pantallas que ya pasan nombre con extensión no dupliquen .xlsx.

5.2 Detalle técnico — SQL Server

No hay cambio en IXONLINE/SQL. La exportación no invoca SPQ_FTR_COL ni METODO documentado; es lectura genérica de la tabla FTRE desde el frontend.

5.3 Detalle técnico — Backend (qrystalos.server)

No aplica. El endpoint /read y el contrato de FTRE permanecen iguales.

6. Qué tener en cuenta

  • El defecto es de nombre de archivo, no de permisos ni de volumen de datos (el cliente reportó ~1 MB descargado).
  • Chrome y Edge guardan el blob con el nombre que entrega writeFile; la corrección es solo cliente.
  • Si en el futuro se unifica exportación en Rlot/Keyboard, conviene el mismo helper de extensión (fuera de este REQ).
  • Material de capacitación y paliativo (.xlsx manual) quedó en el paquete del caso para soporte hasta liberar el fix.
