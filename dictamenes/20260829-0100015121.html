1. Requerimiento del cliente

Al editar la forma de pago en caja, el sistema no actualiza correctamente FCJ.VALORTOTAL: conserva el monto total anterior en lugar de recalcularse con el valor editado, por lo que el documento puede quedar confirmado con un total incorrecto o el usuario ve un «valor a pagar» distinto al real. Cliente: ARTMEDICA.

Criterios de aceptación

  • Validar que el problema sigue presente al insertar/editar forma de pago (PCJ).
  • FCJD no debe modificarse al insertar o editar PCJ (ej.: FCJD = 1.000 permanece aunque PCJ sea 500).
  • FCJ.VALORTOTAL debe conservar el total del concepto (SUM(FCJD)), no recalcularse desde PCJ.
  • Confirmación solo cuando SUM(PCJ) = FCJ.VALORTOTAL.
  • No afectar el libre proceso de escoger distintas formas de pago.

Validar antes de desarrollar

Obligatorio. Este REQ ya se trabajó. Antes de tocar código, el desarrollador debe comprobar que el error no se haya corregido en un trabajo previo.
  • En el ambiente del cliente (rama hotfix/IXCOLO236 / ARTMEDICA), reproducir: recibo PROCEDENCIA ≠ CAJA → editar o insertar forma de pago (PCJ) por un monto distinto al FCJD (ej. FCJD = 1.000, PCJ = 500).
  • Validar datos: FCJD no debe cambiar; FCJ.VALORTOTAL debe seguir en 1.000; pendiente = 500.
  • Si el proceso ya funciona: no aplicar la propuesta de este dictamen; informar que está correcto.
  • Si el fallo sí se reproduce (FCJD o VALORTOTAL se pisan): recién entonces aplicar la sección de propuesta.

Resumen ejecutivo

El error no es «falta recalcular VALORTOTAL desde PCJ», sino lo contrario: varias ramas de SPQ_CONF_CAJA **pisan FCJD y/o FCJ.VALORTOTAL** cuando el usuario inserta o edita una forma de pago. Ejemplo coordinador: FCJD = 1.000 → inserto PCJ = 500 → FCJD debe seguir en 1.000 y FCJ.VALORTOTAL en 1.000; pendiente = 500 hasta completar el pago. Rama más grave: CRUDFPA_EGRESO / EDITAR ejecuta UPDATE FCJD y UPDATE FCJ con @VALOR (líneas ~1379-1380), reduciendo el concepto de 1.000 a 500 y permitiendo confirmar con total incorrecto. También afectan INSERTAR en CRUDFPA_EGRESO (~1307-1326), bloques en CRUDFPA_2 INSERTAR (~1712-1713), ELIMINA_FPA_EGRESO (~1129-1130) y SPK_TOTPCJ_EG cuando COP_VALPCJ='SI' (sincroniza FCJD desde SUM(PCJ)).

6. Cambios propuestos

6.1 Frontend (Qrystalos2)

Sin cambio obligatorio. El FE ya envía PROCESO: 'Editar' y refresca montos desde la respuesta del SPQ. Opcional: tras guardar FPA, forzar DETALLE_MOVIMIENTO si el SPQ no devuelve montos coherentes.

6.2 SQL Server — SPQ_CONF_CAJA

Objeto principal: SPQ_CONF_CAJA. Todas las correcciones deben condicionarse a FCJ.PROCEDENCIA <> 'CAJA'. Para procedencia CAJA, conservar la lógica actual salvo regresión demostrada. No invocar SPK_TOTPCJ_EG tras insert/edit PCJ cuando procedencia ≠ CAJA — ese SPK pisa FCJD desde SUM(PCJ).

Patrón recomendado (envolver bloques existentes)

SELECT @PROCEDENCIA = PROCEDENCIA FROM FCJ WHERE CODCAJA = @CODCAJA AND CNSFACJ = @CNSFACJ

-- Tras UPDATE/INSERT/DELETE PCJ:
IF UPPER(COALESCE(@PROCEDENCIA,'')) <> 'CAJA'
BEGIN
    -- Solo validar: SUM(PCJ) no debe superar FCJ.VALORTOTAL
    -- NO ejecutar UPDATE FCJD / UPDATE FCJ.VALORTOTAL
END
ELSE
BEGIN
    -- Mantener recálculo actual (CAJA)
END

A) Rama CRUDFPA_EGRESO → EDITAR (prioridad)

Condicionar (~1379-1380) a PROCEDENCIA = 'CAJA'. Si ≠ CAJA: dejar únicamente el UPDATE PCJ.

B) Rama CRUDFPA_EGRESO → INSERTAR

Condicionar bloques ~1307-1326 a PROCEDENCIA = 'CAJA'. Si ≠ CAJA: solo INSERT PCJ; validar SUM(PCJ) ≤ FCJ.VALORTOTAL.

C) Rama CRUDFPA_2 → INSERTAR

Condicionar bloque ~1712-1713 a PROCEDENCIA = 'CAJA'. Rama EDITAR: ya correcta (solo UPDATE PCJ).

D) Rama ELIMINA_FPA_EGRESO

Condicionar bloque ~1129-1130 a PROCEDENCIA = 'CAJA'. Si ≠ CAJA: eliminar PCJ no reduce FCJD/FCJ.

E) Ingreso CRUDFPA

EDITAR ya solo toca PCJ — OK. Revisar INSERTAR/ELIMINA_FPA con la misma regla de procedencia.

F) SPK_TOTPCJ_EG

Si COP_VALPCJ='SI', pisa FCJD con SUM(PCJ). No invocar tras insert/edit PCJ cuando procedencia ≠ CAJA.

G) FCJ.VALORTOTAL — cuándo sí actualizar

Operaciones de detalle FCJD (INSERTA_FCJD, DELETE_FCJD) — patrón existente ~3069:

UPDATE FCJ SET VALORTOTAL = (SELECT SUM(VALORTOTAL) FROM FCJD WHERE ...)
