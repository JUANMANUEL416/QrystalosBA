1. Requerimiento del cliente

SE REQUIERE QUE ESTA VALIDACION DE PUEDA ACTIVAR O DESACTIVAR POR VARIABLE se debe crar la variable y adiconar el mensaje de es necesario definir las prestaciones que estan sin pedir a inventario

Criterios de aceptación

1) Existe variable USVGS nueva (valores SI/NO; valor por defecto acordado con negocio, recomendado SI para no cambiar sitios que ya exigen pedido). 2) Con variable = SI: al intentar Reorganizar (METODO REORGANIZAR_TODO) o Facturar responsable/todo en Cargos SOAT, si hay ítems de inventario sin pedir (HPRE/HPRED: ESDEINV=1, PEDIDOINV=0, no facturados, NOCOBRABLE≠1), el sistema responde KO y muestra el mensaje: «Es necesario definir las prestaciones que están sin pedir a inventario» (puede listar NOPRESTACION en el detalle ERROR). 3) Con variable = NO: esas operaciones no se bloquean por ítems sin pedir (comportamiento actual de sitios que hoy no validan en SQL). 4) El filtro «Sin pedir inv» y pedir/deshacer pedido (SPQ_HPRE · PEDIR_INV / DESHACER_PEDIDO) siguen operativos; la variable no los oculta. 5) Prueba en preversión: admisión SOAT como la captura (cirugías con mezcla pedido/sin pedir); contrastar Reorganizar y Facturar con variable ON/OFF.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy, en accidentes SOAT, el usuario puede reorganizar la repartición de cargos entre aseguradora, ADRES y EPS, o facturar, aunque queden medicamentos/insumos marcados como de inventario sin haber pedido a farmacia. El cliente quiere poder encender o apagar una regla de negocio con una variable de configuración: cuando esté encendida, el sistema debe detener Reorganizar y Facturar y decir claramente que hay prestaciones pendientes de pedir a inventario; cuando esté apagada, no aplicar esa regla. El filtro de pantalla para ver esos cargos y los botones de pedir/deshacer pedido siguen igual.

5.1 Detalle técnico — Frontend (Qrystalos2)

  • src/components/asistencial/HPRESOATComponent.vue: en bloque de variables (~SOATBLOQSALDONEG), agregar getUsvgs('SOATVALSINPEDIRINV') con default SI.
  • Opcional: antes de onReorganizar / onFacturar, si variable=SI, consulta read o reutilizar datos cargados para contar ítems sin pedir; mostrar notify con texto del REQ (no sustituir validación SQL).
  • No eliminar MENSAJE_PEDIDO_INV_BLOQUEADO para edición con PEDIDOINV=1 salvo decisión explícita de negocio.

5.2 Detalle técnico — SQL Server

En SPQ_DISTRIHPRED_SOAT, al inicio de REORGANIZAR_TODO y FACTURAR (después de leer @NOADMISION / parámetros): IF UPPER(LTRIM(RTRIM(dbo.FNK_VALORVARIABLE('SOATVALSINPEDIRINV')))) = 'SI' BEGIN IF EXISTS ( SELECT 1 FROM HPRED D INNER JOIN HPRE H ON H.NOPRESTACION = D.NOPRESTACION WHERE H.NOADMISION = @NOADMISION AND COALESCE(D.FACTURADA,0) = 0 AND COALESCE(D.NOCOBRABLE,0) = 0 AND COALESCE(H.ESDEINV,0) = 1 AND COALESCE(H.PEDIDOINV,0) = 0 ) BEGIN SELECT 'KO' OK SELECT ERROR = N'Es necesario definir las prestaciones que están sin pedir a inventario' -- Opcional: segundo recordset con NOPRESTACION distintos RETURN END END Releer PREVERSION completa antes de merge: verificar validaciones existentes por pedido activo para no duplicar.

5.3 Detalle técnico — Backend (qrystalos.server)

Sin cambio de contrato: POST /json con MODELO DISTRIHPRED_SOAT existente. Verificar que recordsets[1] con ERROR dispare Aviso Importante (interceptor axios).

6. Qué tener en cuenta

  • Nombre final de USVGS debe reservarse en catálogo global (evitar colisión con variables SOAT existentes).
  • ESDEINV en HPRE proviene de PRE.MINVENTARIOS al cargar servicios; validar con prefijo cirugías (captura 0021).
  • REQ 6336: pedir inventario desde SOAT en UI puede seguir incompleto; esta validación no lo reemplaza.
  • Performance: EXISTS indexado por NOADMISION en HPRE/HPRED; evitar cursor extra.
