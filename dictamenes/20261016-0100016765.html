1. Requerimiento del cliente

Notas no reflejadas en presupuesto: movimientos que no concuerdan con la cartera. Soporte solicita mejoras en la ventana de notas: • Filtro de tipo de nota. • Filtro por cuenta de cobro, CNS de la nota y número de factura. • Columna de procedencia (NOTAS, GLOSAS, CONCILIA, etc.). • Corregir duplicación de filas en el listado.

2. Análisis del coordinador

Paso 0 — clasificación: defecto en consulta + hueco UX (no capacitación). La captura corresponde a Presupuesto → Reportes → Notas Crédito (#/ppto/infoppto/lista_fnot), no a Movimientos → Notas DB CR (PTNOT). Control — caminos: (1) consulta automática vía AppStore.read Tabla FNOT al cambiar filtros; (2) Enviar a Presupuesto / Enviar Filtro → MODELO PPTO_REP · PRESUPUESTO_FNOT; (3) Imprimir PDF en cliente; (4) Exportar → PPTO_REP · EXPORT_FNOT. Causa raíz duplicación: INNER JOIN FTR → PLN (varias filas PLN por IDPLAN) y posible producto con VWK_TEXCA; la misma FNOT aparece N veces con mismos datos (p. ej. 02C00077171 ×4). Infla contadores y puede repetir envíos masivos. Notas «no reflejadas»: muchas tienen ENPRESUPUESTO=0 (pendientes de envío); el listado erróneo impide operar. Envío válido: PRESUPUESTO_FNOT → ENVIA_NOTADBCR_PPTO (ficha leída en base presupuesto). Métodos documentados cubren alcance; no se exige bajar SPQ_PPTO_REP al caso salvo releer línea exacta de EXPORT_FNOT al implementar.

Criterios de aceptación

  1. Cada nota FNOT (CNSFNOT + CLASE) aparece una sola vez en grilla, PDF y Excel; contadores Registros / Enviados / No enviados = notas únicas.
  2. Filtros: tipo nota (Crédito/Débito/Todas), CNSFNOT, N_FACTURA, CNSCXC (parcial), además de los existentes.
  3. Columna Procedencia legible desde FNOT.PROCEDENCIA y señales (p. ej. CNSGLO → GLOSA).
  4. Enviar Filtro: un intento por CNSFNOT pendiente.
  5. PRESUPUESTO_FNOT sin regresión; ENPRESUPUESTO=1 no reenvía.
  6. Prueba ASOCABILIDOS: consecutivos duplicados en captura quedan en una fila.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy la pantalla de notas de cartera para presupuesto repite la misma nota varias veces y los totales no cuadran con la cartera. Se corrige la consulta para mostrar una fila por nota, se agregan filtros por tipo, consecutivo, factura y cuenta de cobro, y se ve de dónde viene cada nota (glosa, conciliación, etc.). El botón de envío masivo dejará de intentar enviar la misma nota repetida.

5.2.1 Fragmentos SQL (especificación)

Especificación para desarrollo en IXONLINE/SQL. No ejecutar desde Qrystalos BA.

-- SPQ_PPTO_REP · METODO EXPORT_FNOT
-- Problema: INNER JOIN PLN ON FTR.IDPLAN = PLN.IDPLAN duplica filas por nota.

;WITH FNOT_BASE AS (
  SELECT FNOT.CNSFNOT,
         FNOT.CLASE,
         /* demás columnas del SELECT actual */,
         ROW_NUMBER() OVER (
           PARTITION BY FNOT.CNSFNOT, FNOT.CLASE
           ORDER BY COALESCE(NULLIF(RTRIM(PLN.RUBRO), ''), 'zzz'), PLN.RUBRO_ID
         ) AS rn
  FROM FNOT
  INNER JOIN FTR ON FNOT.N_FACTURA = FTR.N_FACTURA
  INNER JOIN PLN ON FTR.IDPLAN = PLN.IDPLAN
  /* joins y WHERE existentes del bloque EXPORT_FNOT */
)
SELECT /* columnas */ INTO #FNOT_EXPORT FROM FNOT_BASE WHERE rn = 1;
