1. Requerimiento del cliente

Solicitud de campo para descarga masiva en Recaudo de Banco El usuario reporta que al procesar una cantidad masiva en el campo de Recaudo de Banco, muchas facturas quedan huérfanas, lo que obliga a desmarcar cada una de ellas de forma manual. Solicita la creación de un campo que permita realizar esta acción de manera masiva. 1. Acceder al módulo de Recaudo de Banco. 2. Procesar una cantidad masiva. 3. Observar que muchas facturas quedan huérfanas. DETALLE: Se solicita escalar el presente requerimiento al área de Desarrollo, debido a que actualmente el módulo de Recaudo, en la opción de Facturas Huérfanas, únicamente permite desmarcar de forma individual.

2. Análisis del coordinador

Paso 0. El título habla de un campo de descarga masiva en Recaudo de Banco. Las capturas muestran otra cosa: el diálogo Facturas huérfanas (MARCAPAGO sin recaudo activo), con 97 y 497 filas y un Desmarcar por fila. Carga masiva es el otro botón (Excel del recaudo) y no es este pedido. Clasificación: hueco. El camino individual ya existe y hace lo correcto. No es capacitación: el usuario ya está en el diálogo y el botón de una fila no cubre el lote. Tampoco es un defecto de ese botón. Hoy, Facturas huérfanas llama a SPQ_FPAG_COL · LISTAR_FACTURAS_HUERFANAS. Trae las cuentas del tercero (y de TERFU) con saldo, MARCAPAGO = 1 y sin vínculo en un recaudo abierto: ni en RPDX ni en FPAGD de un FPAG sin cerrar. Desmarcar llama a LIBERAR_MARCAPAGO con LIBERAR = 1. Si la fila es huérfana, el procedimiento pone MARCAPAGO = 0 (tipo G por número, tipo y glosa; el resto por número, tipo y cuenta) y responde ESTADO LIBERADA. La factura vuelve a la grilla de pendientes. Si está en el plano o en el detalle de un recaudo abierto, no la libera. Eso es una llamada y una confirmación por fila. Con 497 filas el usuario repite el gesto 497 veces. El tipo del ticket es rendimiento. SPK_BORRAPAGO también apaga MARCAPAGO, pero borra FPAGDI/FPAGD abiertos y recalcula el pago: no sirve para huérfanas. Contabilidad: no afecta. Solo cambia la marca de la cuenta por cobrar. No hay asiento, comprobante ni pago.

Criterios de aceptación

  1. En el diálogo Facturas huérfanas del recaudo aparece el botón Desmarcar todas, junto a Actualizar. Solo se habilita si el listado tiene filas.
  2. Al confirmar, una sola llamada libera todas las facturas huérfanas del tercero (el listado completo, no la página de 10). Cada una queda con MARCAPAGO en 0 y vuelve a la grilla de pendientes.
  3. La confirmación muestra la cantidad y permite cancelar. Si se cancela, ninguna marca cambia.
  4. El Desmarcar de cada fila sigue igual: una factura y su propia confirmación.
  5. Desmarcar seleccionadas libera solo las claves marcadas, y solo si en ese momento siguen siendo huérfanas. Una factura que esté en un recaudo abierto (RPDX o FPAGD de un FPAG sin cerrar) no se desmarca.
  6. La respuesta informa cuántas se liberaron. El diálogo se actualiza y la grilla de pendientes se refresca.
  7. No se borran renglones del recaudo, no se anula el pago y no se genera comprobante.

Alcance y restricciones

Alcance: Proceso Cartera · Recaudos (FPAG), diálogo Facturas huérfanas del recaudo del tercero. El mismo diálogo gana Desmarcar todas y Desmarcar seleccionadas. Método nuevo LIBERAR_MARCAPAGO_MASIVO en SPQ_FPAG_COL. Canal existente AppStore.json, MODELO FPAG_COL.

Fuera: Carga masiva Excel/plano, resto del recaudo, exportación a Excel, módulos nuevos.

Restricciones: No recorrer el listado llamando LIBERAR_MARCAPAGO una vez por factura. No usar SPK_BORRAPAGO ni BORRARTODO. No desmarcar facturas en recaudo abierto ni de otro tercero. Tipo G por factura, tipo y glosa; el resto por factura, tipo y cuenta por cobrar. Confirmar antes de ejecutar. La paginación de 10 filas no limita la acción masiva.

5.0 En palabras simples (negocio)

En Facturas huérfanas, Desmarcar todas pide confirmación con la cantidad y quita de una vez la marca de las facturas que quedaron marcadas sin un recaudo abierto, para que vuelvan a la grilla de pendientes. Nuevo método LIBERAR_MARCAPAGO_MASIVO en SPQ_FPAG_COL (IXONLINE/SQL). Población: la de LISTAR_FACTURAS_HUERFANAS. Efecto: el UPDATE de LIBERAR_MARCAPAGO con LIBERAR=1, en una sentencia. Parámetros JSON: IDTERCERO obligatorio; TODAS=1 o lista FACTURAS con N_FACTURA, TIPO, CNSCXC/CNSGLO según tipo G o no. Respuesta: OK, ESTADO LIBERADA, CANTIDAD = @@ROWCOUNT.

No invocar LIBERAR_MARCAPAGO en ciclo. No usar SPK_BORRAPAGO.

5.2.1 Fragmentos SQL (especificación)

Especificación para el desarrollador. No ejecutar desde la oficina de coordinación.

-- Objeto: SPQ_FPAG_COL (IXONLINE/SQL). Método nuevo: LIBERAR_MARCAPAGO_MASIVO.
-- Población: la de LISTAR_FACTURAS_HUERFANAS. Efecto: el UPDATE de LIBERAR_MARCAPAGO.
-- Una sentencia. No llamar LIBERAR_MARCAPAGO en ciclo. No usar SPK_BORRAPAGO.

IF @METODO = 'LIBERAR_MARCAPAGO_MASIVO'
BEGIN
    DECLARE @TODAS BIT = 0
    SELECT @IDTERCERO = LTRIM(RTRIM(JSON_VALUE(@PARAMETROS, '$.IDTERCERO')))
         , @TODAS = COALESCE(TRY_CAST(JSON_VALUE(@PARAMETROS, '$.TODAS') AS BIT), 0)

    IF COALESCE(@IDTERCERO, '') = ''
    BEGIN
        SELECT 'KO' OK, 'IDTERCERO es obligatorio.' ERROR
        RETURN
    END

    IF @TODAS = 0 AND JSON_QUERY(@PARAMETROS, '$.FACTURAS') IS NULL
    BEGIN
        SELECT 'KO' OK, 'Indique TODAS=1 o la lista FACTURAS.' ERROR
        RETURN
    END

    UPDATE D
       SET MARCAPAGO = 0
    FROM FCXCDV D
    INNER JOIN FCXC X ON D.CNSCXC = X.CNSCXC
    WHERE D.SALDONETO > 0
      AND D.MARCAPAGO = 1
      AND (
            X.IDTERCERO = @IDTERCERO
            OR X.IDTERCERO IN (SELECT IDTERCEROFU FROM TERFU WHERE IDTERCERO = @IDTERCERO)
          )
      AND NOT EXISTS (
            SELECT 1
            FROM RPDX R
            INNER JOIN FPAG P ON P.CNSRPDX = R.CNS AND P.CERRADO = 0
            WHERE (R.CNS1 = D.N_FACTURA OR R.ID1 = D.N_FACTURA)
              AND COALESCE(R.GRUPOETAREO, R.ID2, '') = D.TIPO
              AND (D.TIPO <> 'G' OR COALESCE(R.CNS5, '') = COALESCE(D.CNSGLO, ''))
          )
      AND NOT EXISTS (
            SELECT 1
            FROM FPAGD FD
            INNER JOIN FPAG P ON P.CNSFPAG = FD.CNSFPAG AND P.CERRADO = 0
            WHERE FD.N_FACTURA = D.N_FACTURA
              AND FD.CLASE = D.TIPO
              AND (D.TIPO <> 'G' OR COALESCE(FD.CNSGLO, '') = COALESCE(D.CNSGLO, ''))
          )
      AND (
            @TODAS = 1
            OR EXISTS (
                SELECT 1
                FROM OPENJSON(JSON_QUERY(@PARAMETROS, '$.FACTURAS')) J
                WHERE JSON_VALUE(J.[value], '$.N_FACTURA') = D.N_FACTURA
                  AND JSON_VALUE(J.[value], '$.TIPO') = D.TIPO
                  AND (
                        (D.TIPO = 'G' AND COALESCE(JSON_VALUE(J.[value], '$.CNSGLO'), '') = COALESCE(D.CNSGLO, ''))
                     OR (D.TIPO <> 'G' AND JSON_VALUE(J.[value], '$.CNSCXC') = D.CNSCXC)
                  )
            )
          )

    SELECT 'OK' OK
         , 'LIBERADA' ESTADO
         , @@ROWCOUNT CANTIDAD
         , 'Facturas liberadas. Ya pueden aparecer en CXC para recaudo.' MENSAJE
    RETURN
END

6. Qué tener en cuenta

  • El REQ habla de «descarga masiva»; el arreglo es desmarcado masivo de huérfanas, no exportación Excel (control distinto en el mismo recaudo).
