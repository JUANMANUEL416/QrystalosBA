1. Requerimiento del cliente

Si la factura no se puede enviar a Sunat, el usuario debe saber por qué. Hoy el envío se interrumpe y la factura sigue sin notificar, con un texto de que se está enviando a contabilidad. Origen comité SR20261006-022: defecto peru-envio-silencioso en el control de envío MiFact al cerrar / notificar factura.

2. Análisis del coordinador

Clasificación: defecto (no capacitación). Proceso json-peru · control enviar-sunat-ftr. Paso 0 — ¿Ya existe el envío SUNAT? Sí; el usuario usa Cerrar Factura / Notificar Sunat en Facturación PE. El fallo es que varias salidas anticipadas del SPK no propagan error y la pantalla muestra éxito genérico de contabilidad. Caminos del control inventariados: • Cerrar Factura / Notificar Sunat (MiFact) → AppStore.json FTR_COL · ENVIA_CONTAB. • Notificar Sunat SAP → FTR_PERU · ENVIAR_FACTURA_SAP (fuera de alcance). • Corregir / Quitar Error → reintentos (sin cambio de alcance). • Columna Est.Sunat y mensaje en detalle (FACTEP / RAZONANULACION). Causa técnica: SPK_GENERA_JSON_PERU_FACTURA y SPK_GENERA_JSON_PERU_FTR_INTEGRA hacen RETURN con PRINT cuando ya hay FTRE, afecto+inafecto ≤ 0, token < 20, URL < 30, JSON vacío o FACTEP en 101/102/103. SPQ_FTR_COL · ENVIA_CONTAB ejecuta el SPK, sigue con SPK_NC_CONTAB_FTR y devuelve OK. FTRPeComponent.vue · EnviarContabilidad muestra «Registro Enviando a Contabilidad» si OK=OK. Contabilidad: no cambia asientos ni MCUE/CON; solo mensajería y criterio de no devolver OK engañoso antes de contabilizar si SUNAT no salió (validar con negocio en pruebas).

Criterios de aceptación

  1. Token < 20 caracteres o URL API < 30: mensaje explícito; Est.Sunat Sin Notificar.
  2. Base afecta+inafecto ≤ 0 (reglas PAQUETE del SPK): mensaje explícito; no aviso verde de contabilidad como si SUNAT hubiera salido.
  3. FTRE ya existente: informar que el comprobante ya fue enviado; no duplicar POST.
  4. Omisión por FACTEP 101/102/103 en reintento: informar al usuario.
  5. Envío válido MiFact: comportamiento actual (FACTEP, FTRE, FTRAPILOG, contabilización).
  6. Tras el botón, la grilla y el detalle reflejan Est.Sunat y el mensaje visible coherente con el resultado.

Alcance y restricciones

Alcance: Control enviar-sunat-ftr · botones Cerrar Factura y Notificar Sunat (MiFact). SPQ_FTR_COL · ENVIA_CONTAB, SPK_GENERA_JSON_PERU_FACTURA, SPK_GENERA_JSON_PERU_FTR_INTEGRA, FTRPeComponent.vue.

Fuera de alcance: Notas NC/ND (FNOT_ENVIARSUNAT), Notificar Sunat SAP (INTER_SAP), permisos USGRUH (SR20261006-023), cambio de proveedor o JSON.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy, si falta configuración, no hay valores gravables o el comprobante ya se envió, el sistema calla y el usuario ve un mensaje verde de «envío a contabilidad» aunque la factura siga Sin Notificar ante SUNAT. Se propone que cada uno de esos casos muestre el motivo en pantalla y que no aparezca éxito cuando SUNAT no recibió el envío.

5.1 Detalle técnico — Frontend (Qrystalos2)

Ruta: /admin/facturacionPe · FacturacionPePage → FTRPeComponent.vue.

  • EnviarContabilidad: si recordset[0].OK !== 'OK', mantener notify negativo con ERROR (ya existe); si OK, diferenciar mensaje Perú: éxito solo cuando SUNAT/contabilización corresponda; no usar siempre «Registro Enviando a Contabilidad» cuando el backend devuelve aviso de omisión SUNAT.
  • Tras la respuesta, tableRef.obligarRefrescar() y refrescar detalle para Est.Sunat y texto en rojo (FACTEP / RAZONANULACION).
  • Regresión: botones Corregir, Quitar Error, Notificar Sunat SAP sin cambio de alcance.
