1. Requerimiento

Tras documentar el módulo CxP (6 pestañas), se identificaron defectos funcionales en operaciones cotidianas y un flujo Radian→CxP más lento de lo necesario. Fase 1 — Defectos (obligatorio): 1. «Eliminar todos» los ítems del detalle FCXPD no borra líneas (el usuario confirma pero no hay efecto). 2. El menú «Aplicar anticipo» en la grilla FCXP no aparece cuando debería (typo en condición de visibilidad). Fase 2 — Optimización Radian (mejora): 3. Generar CxP desde factura recibida Radian debe ser más rápido: hoy exige cambio de pestaña, guardado manual de cabecera y N llamadas secuenciales CRUD_FCXPD. Existe en backend el METODO REGISTRAR_CXP_FRADIAN (cabecera + detalle en una transacción) que el frontend no utiliza. Fase 3 — Documentación (fuera de alcance desarrollo): profundizar tabs Auditoría, Orden de pago, Anticipos e Informes (turno siguiente).

Criterios de aceptación

Fase 1 • Con CxP no contabilizada, menú eliminar detalle → «Eliminar todos» borra todas las líneas FCXPD y recalcula totales. • Con FCXP CONTABILIZADA=1 y SALDO>0, menú contextual muestra «Aplicar anticipo» (misma regla que otras opciones con SALDO). Fase 2 • Desde tab Facturas Radian, «Generar CxP» completa registro con ≤3 llamadas API en el camino feliz (ARCHIVOS + REGISTRAR_CXP_FRADIAN [+ RECONSTRUIR si KMCOM automático]). • FRADIAN.REGISTRADA_CXP=1 y FCXP creada con NOREFERENCIA = NODOCUMENTO y detalle desde XML. • Modal CC/cuenta se mantiene cuando falten datos contables obligatorios; si CXP_KMCOM_AUTOMATICO=SI y cuentas resueltas, permitir generación sin modal (configurable). • No regresión: conciliación masiva CONCILIAR_CXP_FRADIAN sigue operativa. • Factura con tercero inexistente: mensaje claro sin cambio de comportamiento.

2. Análisis del coordinador

Proceso: conocimiento/cxp-fcxp · documentado 2026-09-17. Paso 0 — Clasificación: • Eliminar todos / Aplicar anticipo → defecto (camino existe, falla condición o parámetros). • Radian lento → mejora (hueco de diseño: SP batch disponible, FE usa flujo multi-paso legacy). Defecto 1 — ELIMINAR_FCXPD todos: SPQ_FCXP · ELIMINAR_FCXPD (sql/ PREVERSION=2.0.1) implementado: PROCEDE=1 elimina ITEM; PROCEDE=2 elimina todas las líneas. CXPComponent.onBorrarDetTodos (~27807) solo envía CNSFCXP sin PROCEDE → ninguna rama DELETE ejecuta. onBorrarDet(dato, 1) sí envía PROCEDE=1 (una línea OK). Defecto 2 — Aplicar anticipo: CXPComponent ~1187: v-if props.row.SALUD <= 0. Campo correcto es SALDO. SALUD no existe en FCXP → condición casi siempre falsa → oculta menú. Radian hoy (FacturasRadianComponent + CXPComponent): ARCHIVOS → parse XML FE → irATabCxp → resolverInstanciaCxp (poll hasta 30 intentos) → abrirCxpDesdeRadian → usuario CRUD_FCXP → modal CxpFradianDetalleContableDialog (CC/cuenta) → bucle await CRUD_FCXPD por línea → RECALCULAR_FCXP → VINCULAR_CXP_FRADIAN (no existe en SPQ_FCXP DESAIX) → fallback CONCILIAR_CXP_FRADIAN. Alternativa backend (sin inventar): REGISTRAR_CXP_FRADIAN recibe CNSRADIAN + dataFCXP + detalleFCXPD JSON; INSERT FCXP + FCXPD en una transacción; UPDATE FRADIAN.REGISTRADA_CXP=1; SPK_CALCULOVALORESCXP; valida periodo PRI; sincroniza CUFE si existe SPK_SINCRONIZAR_CUFE_RADIAN. Round-trips estimados (10 líneas): hoy ~15 API · propuesto 2–3. Contabilidad: no cambia reglas MCP; las cuentas CC/CUENTA_SER siguen siendo obligatorias antes de CONTABILIZAR_FCXP.

(3) Radian sin CxP → medir tiempo/clicks flujo actual vs prototipo REGISTRAR. Si (1) ya funciona en algún build, verificar parámetros en red.
  • USVGS CXP_KMCOM_AUTOMATICO en cliente piloto (SI/NO).

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy, quien recibe facturas por Radian debe cambiar de pestaña, guardar la cabecera y esperar mientras el sistema graba línea por línea; además «eliminar todo el detalle» y «aplicar anticipo» fallan por errores de pantalla. Se corregirán esos dos fallos y se usará el registro único que ya existe en el sistema para crear la cuenta por pagar completa en un solo paso, asignando centros de costo y cuentas cuando haga falta.

5.1 Detalle técnico — Frontend (Qrystalos2)

  • F1 — CXPComponent.vue: onBorrarDetTodos agregar PROCEDE: 2; corregir SALUD→SALDO en v-if menú anticipo.
  • F2 — FacturasRadianComponent.vue: flujo generarCXP:
    1. ARCHIVOS + parse (igual).
    2. Validar tercero y periodo (reutilizar validarPeriodoAbiertoParaCxP o confiar validación SP).
    3. Abrir CxpFradianDetalleContableDialog en tab Radian (mover import del dialog o exponer vía composable).
    4. POST { MODELO:'FCXP', METODO:'REGISTRAR_CXP_FRADIAN', PARAMETROS:{ CNSRADIAN, dataFCXP, detalleFCXPD } }.
    5. Si OK: notificar CNSFCXP, refrescar grilla, limpiar xmlCache.
    6. Si CXP_KMCOM_AUTOMATICO=SI: opcional RECONSTRUIR_CUENTAS_FCXPD.
  • Mantener flujo asistido actual como fallback «Modo detallado» si negocio lo pide (feature flag o botón secundario).
  • Eliminar poll resolverInstanciaCxp en camino rápido.

5.2 Detalle técnico — SQL Server

Sin cambio obligatorio. REGISTRAR_CXP_FRADIAN ya en sql/SPQ_FCXP.sql (PREVERSION=2.0.1). Opcional: METODO VINCULAR_CXP_FRADIAN UPDATE FRADIAN SET REGISTRADA_CXP=1 WHERE CNSRADIAN=@CNSRADIAN AND EXISTS (SELECT 1 FROM FCXP WHERE CNSFCXP=@CNSFCXP …) — solo si se desea compatibilidad con FE legacy sin refactor completo de vincularFradianTrasCxp.

5.3 Detalle técnico — Backend (qrystalos.server)

Sin cambio de contrato: MODELO FCXP enruta a SPQ_FCXP existente.
