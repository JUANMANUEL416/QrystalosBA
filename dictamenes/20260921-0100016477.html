1. Requerimiento del cliente

Agregar en el filtro de sede una opción que consulte todas las sedes, bloqueando a su vez la facturación para que no se puedan realizar facturas con la sede «Todos/Todas». Contexto: nueva ventana de facturación de dispensación de medicamentos (Facturación Masiva → Autorizador de medicamentos).

Criterios de aceptación

  1. Combo Id. Sede en FTRMAutComponent ofrece Todas en No PBS y Ambos, además de sedes de FTR_COL · SEDFACUMASI.
  2. Con Todas, la grilla lista AUT de todas las sedes (filtros fecha/estado/PBS/búsqueda); columna Id Sede distingue registros.
  3. Con Todas, no se factura: botón No PBS por fila y masiva PBS bloqueados; mensaje claro.
  4. Con sede concreta, sin regresión en FACTURA_AUT_NOPBS y FACTURAR_MASI_PBS.
  5. Defensa servidor si FACTSEDE=SI (alineado FACTURAR_MASI).
  6. Prueba CEM: tercero 900604350, plan CSRS26, AUT en sede 34 y otra; Todas muestra ambas; facturar exige sede concreta.

2. Análisis del coordinador

Proceso: facturación · control Facturación Masiva → Autorizador de medicamentos (conocimiento/facturacion/proceso.json). Paso 0 — ¿Ya existe? Hueco (no capacitación): el legacy FTRMComponent ya tenía «Todas» en sede; el nuevo FTRMAutComponent la oculta en No PBS/Ambos aunque whereAUT ya soporta consulta sin filtrar IDSEDE. Causa: diseño inicial del autorizador nuevo (solo sedes reales en No PBS) para operación multi-sede del comité. Recomendación: opción B — FE + validación en SPQ_FTR_AUT_DISP_COL en métodos de facturación. Contabilidad: no aplica. SQL documentado para sedes: SPQ_FTR_COL · SEDFACUMASI (leído). SPQ_FTR_AUT_DISP_COL sin ficha en sps.json: releer PREVERSION al codificar defensa servidor.

5. Cambios propuestos

5.0 En palabras simples (negocio)

En el autorizador de medicamentos de Facturación Masiva, agregar la opción «Todas» en el filtro de sede para ver autorizaciones de todas las sedes a la vez; al dejar «Todas» seleccionada no se podrá facturar (ni una por una ni masivo PBS) hasta elegir una sede específica.

5.1 Detalle técnico — Frontend (Qrystalos2)

  • Opciones de sede: Tras cargarSedes (SEDFACUMASI), incluir { value: 'Todas', label: 'Todas' } para NOPBS y AMBOS — patrón FTRMComponent (Sedesftr.unshift). Ajustar sedesOptions computed para no filtrar «Todas» fuera de PBS.
  • watch TIPO_MED: No forzar sede real al pasar de PBS a No PBS si el usuario eligió «Todas»; solo default a sede DPR cuando no hay selección.
  • Consulta: Reutilizar whereAUT existente (sin filtro IDSEDE si filtros.IDSEDE === 'Todas').
  • Facturación: En validarFiltrosFacturar, rechazar siempre IDSEDE Todas/TODAS (mensaje: «Seleccione una sede concreta para facturar»). Deshabilitar onFacturarCabecera / botón factura fila cuando filtro sea Todas. puedeFacturarMasiva debe exigir sede ≠ Todas.
  • USVGS: Mantener lectura FACTSEDE en cargarPrefijos; coherente con mensaje legacy si aplica.

5.2 Detalle técnico — SQL Server

Recomendado: validación al inicio de FACTURA_AUT_NOPBS y FACTURAR_MASI_PBS en SPQ_FTR_AUT_DISP_COL, tomando IDSEDE del JSON de parámetros. Patrón equivalente a SPQ_FTR_MASIVA_COL · FACTURAR_MASI cuando FACTSEDE=SI. Releer objeto en PREVERSION antes de editar.

5.2.1 Fragmentos SQL (especificación) — no ejecutar desde BA:

-- Objeto: SPQ_FTR_AUT_DISP_COL (modelo FTR_AUT_DISP_COL).
-- Patrón: sql_refe/0100016283/SPQ_FTR_MASIVA_COL.sql · FACTURAR_MASI (~L406-415).

DECLARE @IDSEDE_FILTRO VARCHAR(20);
SELECT @IDSEDE_FILTRO = IDSEDE FROM OPENJSON(@PARAMETROS) WITH (IDSEDE VARCHAR(20) '$.IDSEDE');

IF UPPER(LTRIM(RTRIM(COALESCE(@IDSEDE_FILTRO,'')))) IN ('TODAS','TODA','')
   OR @IDSEDE_FILTRO = 'Todas'
BEGIN
   INSERT INTO @TBLERRORES(ERROR)
   SELECT 'Debe seleccionar una sede concreta para facturar. Todas solo sirve para consultar autorizaciones.';
   SELECT 'KO' OK;
   SELECT ERROR FROM @TBLERRORES;
   RETURN;
END
