1. Requerimiento del cliente

Restricción para enviar facturas sin visto bueno y notas de auditoría Se solicita que el sistema impida el envío de facturas a la DIAN si no cuentan con el visto bueno y las notas de auditoría correspondientes, para cumplir políticas internas de facturación, auditoría, devolución y glosas. Detalle: validación en el proceso DIAN que permita el encolado únicamente cuando la factura tenga usuario responsable y notas de auditoría registradas con aprobación. Si falta algún requisito, restringir el envío. Contexto operativo FAMIGO: la auditoría de facturación se registra en Notas de auditoría (FTRAUD); cuando el ciclo termina con aprobación es que debe poder enviarse a la DIAN.

2. Análisis del coordinador

Paso 0 — ¿Ya existe? **No es capacitación.** El control «Notificar a la DIAN» (proceso facturación / dian-xml) documenta encolado por FACTE, fecha del día, cápita/PGP y permisos; **no** exige visto bueno FTRAUD. La captura del caso (Proceso DIAN, factura CFAS311051, Es. Dian Pendiente) muestra una factura encolable hoy sin bloqueo por auditoría. **Clasificación: hueco** (regla de negocio no cableada al encolado). Auditoría FAMIGO: pantalla Notas de auditoría (FTRAUDComponent) → IXONLINE/SQL · **SPQ_FTRAUD** · GUARDAR (ESTADO=0), RESPONDER (0→1), APROBAR (1→2, APRUEBA SI/NO). En versión 2.0.9 **no existe** METODO FACTURA_OK en el SP (aunque el FE puede enviar ese nombre en un botón — validar en FAMIGO si está en uso). SPQ_FTRAUD no modifica FTR.FACTE. Hueco técnico: **SPQ_FTR_COL** · NOTI_DIAN, ENCOLAR_ITEM, ENCOLAR_MASIVO (ACCION=1) y **SPQ_FTRFE_COL** · FE_ENCOLAR actualizan FACTE=1 sin consultar FTRAUD (fichas `leido` con `noValida` FTRAUD). Recomendación: validación **autoritativa en SQL** vía función reutilizable + variable **USVGS** `FTR_EXIGE_VB_DIAN=SI` en FAMIGO. FE: mostrar ERROR del SP (ya implementado en encolado unitario); opcional resumen en encolado masivo. Veredicto releer script encolado: fichas **leídas**; no se requiere releer cuerpo para implementar. SPQ_FTRAUD documentado (PREVERSION = liberada 2.0.9).

Criterios de aceptación

  1. Proceso DIAN: Encolar masivo o por fila — facturas sin visto bueno no pasan a FACTE=1; mensaje claro con número de factura.
  2. Detalle factura: Encolar DIAN (NOTI_DIAN / FE_ENCOLAR) rechaza con el mismo criterio.
  3. Cumple si existe nota FTRAUD ESTADO=2 y APRUEBA=SI y no hay notas ESTADO 0 ni 1. Flujo: GUARDAR → RESPONDER → APROBAR (APRUEBA SI). Rechazo con motivo abre nueva nota ESTADO=0.
  4. Facturas que cumplen encolan igual que hoy (fecha, cápita/PGP, FACTE, permisos).
  5. Masivo: solo encola las del filtro que cumplan; informa encoladas vs bloqueadas por auditoría sin abortar todo el lote.
  6. Regresión: desencolar, XML/PDF, Log Facturas y NC/ND DIAN sin cambio salvo el nuevo bloqueo en facturas de venta.

Alcance y restricciones

Alcance: Colombia · facturas TIPODOC FACTURA · pestaña Proceso DIAN y detalle factura. Validación en SPQ_FTR_COL y SPQ_FTRFE_COL según METODOs anteriores.

Fuera: FNOT_COL (notas DIAN), RIPS/CUV, radicación cartera, ENT_COL (auditoría física depósito), Perú FTRPe. No modificar servicio facturador externo.

Restricciones: Activar con USVGS para otros clientes. Hallazgo documentado: RESPONDER escribe USUARIO, APROBAR valida USURESPTA — fuera de alcance salvo que FAMIGO reporte bloqueos en APROBAR.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Antes de encolar una factura a la DIAN, el sistema comprobará que la factura tenga auditoría registrada en Notas de auditoría con visto bueno (aprobación). Si falta la nota, el responsable o la aprobación, no cambiará el estado DIAN y mostrará un mensaje explicando qué falta. El encolado masivo en Proceso DIAN solo incluirá las facturas que cumplan.

5.2 Detalle técnico — SQL Server

  • Crear FNK_FTR_VB_AUDIT_OK(@N_FACTURA) según fragmentos 5.2.1.
  • Invocar en SPQ_FTR_COL · NOTI_DIAN, ENCOLAR_ITEM (TIPODOC FACTURA), ENCOLAR_MASIVO ACCION=1 (WHERE del UPDATE).
  • Invocar en SPQ_FTRFE_COL · FE_ENCOLAR.
  • Mensaje KO sugerido: «La factura no tiene visto bueno de auditoría (notas FTRAUD). Registre y apruebe en Notas de auditoría antes de enviar a la DIAN.» Incluir @N_FACTURA cuando el METODO lo permita.

5.2.1 Fragmentos SQL (especificación)

Especificación para desarrollo; no ejecutar desde Qrystalos BA.

-- 1) Función auxiliar (nueva)
CREATE OR ALTER FUNCTION dbo.FNK_FTR_VB_AUDIT_OK(@N_FACTURA VARCHAR(16))
RETURNS BIT
AS BEGIN
  DECLARE @exige VARCHAR(2) = dbo.FNK_VALORVARIABLE('FTR_EXIGE_VB_DIAN') -- o mecanismo USVGS vigente
  IF COALESCE(@exige,'') <> 'SI' RETURN 1
  IF NOT EXISTS (
    SELECT 1 FROM FTRAUD WITH (NOLOCK)
    WHERE N_FACTURA = @N_FACTURA AND ESTADO = 2 AND APRUEBA = 'SI'
  ) RETURN 0
  IF EXISTS (
    SELECT 1 FROM FTRAUD WITH (NOLOCK)
    WHERE N_FACTURA = @N_FACTURA AND ESTADO IN (0, 1)
  ) RETURN 0
  RETURN 1
END

-- 2) SPQ_FTR_COL · NOTI_DIAN — antes de UPDATE FTR SET FACTE=1
IF dbo.FNK_FTR_VB_AUDIT_OK(@N_FACTURA) = 0
BEGIN
  SELECT 'KO' AS OK,
    'La factura ' + @N_FACTURA + ' no tiene visto bueno de auditoría (FTRAUD). Apruebe en Notas de auditoría antes de enviar a la DIAN.' AS ERROR
  RETURN
END

-- 3) SPQ_FTR_COL · ENCOLAR_ITEM — rama TIPODOC = 'FACTURA', resolver N_FACTURA desde @CNSFACT

-- 4) SPQ_FTR_COL · ENCOLAR_MASIVO ACCION=1 — añadir al UPDATE:
--   AND dbo.FNK_FTR_VB_AUDIT_OK(FTR.N_FACTURA) = 1
-- Opcional: SELECT N_FACTURA omitidas en segundo recordset

-- 5) SPQ_FTRFE_COL · FE_ENCOLAR — misma validación que NOTI_DIAN

-- Factura sin filas FTRAUD → KO
-- GUARDAR + RESPONDER + APROBAR (APRUEBA=SI) → OK encola

7. Pruebas del desarrollador

  • USVGS FTR_EXIGE_VB_DIAN=SI en preversión FAMIGO.
  • Factura sin FTRAUD: NOTI_DIAN y ENCOLAR_ITEM KO; FACTE permanece 0.
  • Ciclo GUARDAR → RESPONDER → APROBAR (SI): encolado OK.
  • Nota ESTADO=1 sin APROBAR: encolado KO.
  • ENCOLAR_MASIVO: mezcla conformes/no conformes — conteo y FACTE solo en conformes.
  • USVGS ≠ SI: comportamiento idéntico al actual.
  • NOTADB/NOTACR en ENCOLAR_ITEM sin validación FTRAUD (fuera de alcance).
  • Regresión DESCOLA_ITEM, TREA_XML, FNOT_COL.
