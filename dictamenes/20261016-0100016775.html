1. Requerimiento del cliente

En notas crédito generadas por devolución o ajuste de factura de venta de inventario (insumos con IVA), el valor total creditado debe ser base + IVA (ejemplo: NC 01C00000329 sobre factura FVCD1675 — 9 × 198.667 = 1.788.003 + IVA ~339.721 ≈ 2.127.724). Hoy la cabecera FNOT.VR_TOTAL queda solo en base; el PDF (formato fmtFnot01) desalinea columnas; la DIAN puede rechazar CAU02; la contabilidad puede dejar el renglón de IVA en cero. Restricción operativa (16/10/2026): no despliegue en producción CEM salvo acuerdo; se autoriza fix de generación para notas nuevas en PREVERSION o ventana SQL. El paquete completo (contabilidad defensiva, frontend PDF, corrección de NC ya creadas) queda para liberación de comité.

2. Análisis del coordinador

Paso 0 — clasificación: defecto (generación + presentación + contabilidad derivada). No es capacitación. REQ vs captura: el usuario opera devolución parcial desde Inventario → Gestión de ventas (/inv/gesventa), no desde Administrativo → Notas DB/CR. No existe otro control que recalcule la cabecera con IVA en ese camino. Causa: IXONLINE/SQL SPQ_GESVENTA · GEN_NC inserta FNOTD con VALORIVA prorrateado desde FTRD.VIVA, pero en CEM la cabecera quedó con VR_TOTAL = SUM(FNOTD.VR_TOTAL) sin IVA. SPK_GENERAR_XML_DIAN toma totales de cabecera; SPQ_FNOT_IMPRESION · DATOSFNOT alimenta fmtFnot01; SPK_NC_CONTAB_FNOT puede balancear @VDB > @VCR recortando el último DB (IVA a cero) si el CR cartera quedó en base. Evidencia: NC 01C00000329 — VR_TOTAL 1.788.003 vs total esperado ~2.127.724; líneas con VALORIVA coherentes. En canasta PREVERSION (referencia 2.0.7) el fix de cabecera y la defensa contable NC inventario ya están especificados; CEM debe publicar al menos GESVENTA para notas nuevas. Caso histórico y FE PDF quedan para ventana de comité.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Cuando el usuario devuelve parte de una venta de inventario con IVA, la nota crédito debe mostrar y enviar a DIAN y contabilidad el total real (mercancía + IVA). Hoy el sistema guarda bien el IVA en el detalle pero la cabecera queda sin IVA, lo que genera PDF incorrecto, posible rechazo DIAN y asiento con IVA en cero. Se corrige primero la generación de notas nuevas; después, en una ventana de comité, el PDF, la contabilidad defensiva y las notas ya emitidas.

5.2.1 Fragmentos SQL (especificación)

Especificación para desarrollo en IXONLINE/SQL. No ejecutar desde Qrystalos BA.

-- ========== 1) TEMPORAL — IXONLINE/SQL · SPQ_GESVENTA · GEN_NC (PREVERSION) ==========

VALORIVA por linea (prorrateo FTRD.VIVA):
ROUND(CASE WHEN COALESCE(FTRD.CANTIDAD,0) > 0
     THEN FTRD.VIVA * (#DATOS.CANTIDAD_A_DEVOLVER / FTRD.CANTIDAD)
     ELSE COALESCE(FTRD.VIVA,0) END, 2)

Cabecera tras INSERT FNOTD:
SELECT @VLR_TOTAL = SUM(VR_TOTAL), @VLR_IVA = SUM(COALESCE(VALORIVA,0)) FROM FNOTD WHERE CNSFNOT = @CNSFNOT
UPDATE FNOT SET VR_TOTAL = @VLR_TOTAL + @VLR_IVA, VALORCONCEPTO = @VLR_TOTAL + @VLR_IVA WHERE CNSFNOT = @CNSFNOT
