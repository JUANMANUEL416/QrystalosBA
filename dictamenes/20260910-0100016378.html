1. Requerimiento del cliente

Se requiere implementar una funcionalidad que permita configurar los nombres de los conceptos de nómina que serán visualizados en las colillas de pago, específicamente para aquellos conceptos cuya clase sea Manual o Particular. La funcionalidad deberá permitir establecer, a partir de una fecha de aplicación, el nombre que se mostrará para cada concepto en la colilla de pago. Al generar las colillas, el sistema deberá identificar la fecha del período, compararla con la configuración y mostrar el nombre vigente; si no hay configuración, conservar el nombre actual. Aplica únicamente a conceptos Manual o Particular, sin afectar otras clases.

Criterios de aceptación

1. En configuración de nómina, el usuario puede registrar por concepto (solo si NCON.CLASE es Manual o Particular) al menos un registro con fecha de aplicación y texto a mostrar en colilla; no se permite guardar para otras clases. 2. Al imprimir colilla desde prenómina (COLILLAS_PRENOMINA), liquidación (COLILLAS), colillas de pago / envío masivo y cualquier flujo que use el mismo dataset del SP, cada línea Manual/Particular muestra el texto configurado vigente a la fecha del período; sin configuración se mantiene el comportamiento actual. 3. Vigencia: fecha de referencia NPER.FECHAFIN del CNSPAGO; registro con mayor FECHAINI (aplicación) ≤ esa fecha. 4. NCON.DESCRIPCION, liquidación, DIAN y pantallas operativas distintas del PDF de colilla no cambian. 5. Regresión: demás clases y colillas sin configuración idénticas a hoy.

2. Análisis del coordinador

Proceso conocimiento: nomina (gate nuevo colilla-nombres, capa configuración + salida colilla). Estado actual: useNomi → AppStore.json MODELO RPT_NOMINA, METODO COLILLAS o COLILLAS_PRENOMINA; FmtColillasNom.js imprime NOMBRE_CONCEPTO (recordset 3, máx. 60 caracteres). sql/SPQ_RPT_NOMINA.sql (leído en análisis): COLILLAS concatena CODCONCEPTO + NIEPED.NOMBRE_CONCEPTO (+ tercero); COLILLAS_PRENOMINA usa CODCONCEPTO + NCON.DESCRIPCION (+ tercero). No hay tabla de alias documentada en qrystalos.documentacion. Causa: el desprendible no tiene capa de alias por vigencia; liquidación persiste NIEPED.NOMBRE_CONCEPTO y el reporte lo reutiliza. Recomendación: tabla vigencias + CRUD en configuración de conceptos + resolución en SPQ_RPT_NOMINA (y EXPORTA_DATOS_COLILLAS si aplica). FE sin cambio obligatorio si el SP devuelve NOMBRE_CONCEPTO ya resuelto. Releer .sql de hoy: SPQ_RPT_NOMINA en sql/ cubre el gate de impresión; no hace falta releer SPK de prenómina para este REQ. 5. Cambios propuestos

5.0 En palabras simples (negocio)

En configuración de conceptos Manual y Particular se podrá definir, con fecha desde cuándo aplica, cómo se verá el nombre en la colilla de pago. Al imprimir el desprendible, el sistema usará ese nombre para ese período; el resto de conceptos y el nombre oficial del concepto en el sistema no cambian.

5.1 Detalle técnico — Frontend (Qrystalos2)

  • Ruta /nom.config — en edición de concepto con NCON.CLASE Manual o Particular: pestaña o sección «Nombre en colilla» con grilla FECHAINI + texto (referencia ParametrosComponent.vue + NPARV).
  • Llamadas AppStore.json MODELO NOM_CONCEPTOS (METODOs a definir al leer SPQ_NOM_CONCEPTOS.sql).
  • Permisos: reutilizar MENUQ_NOMINA / configuración de conceptos existente.
  • No modificar la lógica de impresión en useNomi/index.js ni FmtColillasNom.js salvo ajuste de longitud si el alias supera 60 caracteres visibles.

5.2 Detalle técnico — SQL Server

Especificación (no ejecutar desde BA): 1) CREATE tabla alias (nombre a confirmar con estándar IX): PK (CODCONCEPTO, FECHAINI), columna texto colilla (varchar acorde PDF), USUARIO/fechas auditoría, FK → NCON.CODCONCEPTO. 2) SPQ_NOM_CONCEPTOS (o SPQ_NOM_NCONCOL): GUARDAR/LISTAR/ELIMINAR vigencias; rechazar si NCON.CLASE NOT IN ('Manual','Particular'). 3) SPQ_RPT_NOMINA · COLILLAS: en SELECT detalle, JOIN NPER (vía NIEPE.CNSPAGO) y OUTER APPLY (TOP 1 … ORDER BY FECHAINI DESC) sobre tabla alias donde NCON.CLASE IN ('Manual','Particular'). Reemplazar expresión: CODCONCEPTO + ' ' + [COALESCE(alias, NIEPED.NOMBRE_CONCEPTO)] + CASE tercero… 4) SPQ_RPT_NOMINA · COLILLAS_PRENOMINA: misma regla con COALESCE(alias, NCON.DESCRIPCION). 5) EXPORTA_DATOS_COLILLAS: aplicar la misma función/expresión en el INSERT KEXCEL_FILL dinámico. Índice sugerido: (CODCONCEPTO, FECHAINI DESC).
