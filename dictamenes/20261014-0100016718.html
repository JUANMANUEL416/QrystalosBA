1. Requerimiento del cliente

Filtrar por estado Sunat o por estado de factura debe mostrar lo que el usuario eligió. Hoy faltan opciones, los códigos no coinciden y dos estados distintos comparten el mismo valor. Alcance de negocio (comité SR20261006-024): filtros de estado Sunat, estado de factura y estado de notas en Perú. No debe cambiarse lo que guarda Sunat ni el envío electrónico.

2. Análisis del coordinador

Clasificación: defecto de interfaz (no capacitación ni hueco funcional). Proceso json-peru · control estados-sunat-dos-nombres. Paso 0 — ¿Ya existe el envío SUNAT? Sí. El fallo es la consulta en pantalla: la grilla usa AppStore.read sobre FTR/FNOT con CondicionAdicional armada en Vue (WFTR / where), no un METODO SPQ de filtrado. Hallazgos en Qrystalos2: • FTRPeComponent — EstaSunat: falta código 103 (Error Valida); etiquetas distintas a la columna Est.Sunat (CASE sobre FACTEP). OpEstadoFac: dos opciones con value NC; el switch de WFTR espera otros literales (Anuladas, En Cxc, Nota Aud…) que no coinciden con P/A/NC/CXC del select → el filtro de estado de factura no aplica condiciones. • NotasDBCRComponent (PERU): Pendiente envía PEN; el WHERE solo reconoce PEND para FACTEP vacío. • fnClaseCol: sin estilo para Rechazado, Rechazado-api y Baja. • FTRGaranteComponent: mismos gaps en EstaSunat (sin 103). Mapeo canónico FACTEP (columna Est.Sunat): vacío → Sin Notificar · 103 → Error Valida · 104 → Rechazado · 104A → Rechazado-api · 105 → Anulada · 108 → Baja · 101/102/otros → OK en columna. Impacto SQL / API: No. Solo frontend.

Criterios de aceptación

  1. Filtro Estado Sunat (Facturas PE): cada opción usa el código almacenado en FACTEP; incluye 103 Error Valida; «Sin notificar» filtra vacío/null con la misma etiqueta que la columna.
  2. Filtro Estado de factura: cada value del select coincide con el switch que arma WFTR; no hay dos opciones con el mismo value; Activas, Anuladas, lote CxC y auditoría FTRAUD filtran según la etiqueta.
  3. Notas (PERU): «Pendiente» lista notas con FACTEP vacío.
  4. Colores: Rechazado, Rechazado-api y Baja distinguibles de OK y Error Valida.
  5. Regresión: filtros DIAN en Colombia (IXCOUNTRY ≠ PERU) sin cambios.
