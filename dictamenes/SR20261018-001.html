FEV-RIPS: reportar todo lo facturado y no ocultar el fallo

Necesidad para el plan de trabajo. No es un dictamen de implementación.

SR20261018-001
2026-10-19
Para comité

1. Necesidad o problema

Al generar el RIPS JSON de una factura electrónica, de una nota o de un ajuste, deben salir todos los servicios y las estancias que ya están en la factura, con el código y el valor que el Ministerio espera. Si la generación falla, el usuario tiene que verlo: el trabajo no puede quedar como terminado. Un ajuste de cápita que no es PGP también debe volver a armar el JSON.

2. Análisis

Clasificación: defecto. No es capacitación ni hueco de pantalla: el camino existe (Administrativo → Facturación → generar RIPS JSON / FEV) y pierde datos o miente el estado.

Confirmados contra IXONLINE/SQL PREVERSION 2.0.10 (idéntica a la liberada):
1. INNER JOIN RIPS_CP por SER.CODIGORIPS: sin homologar, el ítem no entra. SPK_RIPS_JSON_FTR_IND :983 y el resto de hojas.
2. Masiva, capitación masiva y nota de ajuste masiva exigen DATEDIFF(HOUR, ingreso, alta)≤48 en urgencias y hospitalización: omiten estancias de más de 48 h. SPK_RIPS_JSON_FTR_MAS :1389/:1421; CAPMASI :862/:893; NOTAAJUSTE_MAS :1048/:1080.
3. CAPMASI hace UPDATE HADM.FECHA si el alta es anterior al ingreso :835-844.
4. IND: UPDATE del CUM sin paréntesis :1645-1649. En AT de cita, vrUnitOS y vrServicio ambos = FTRD.VLR_SERVICI con cantidadOS = CIT.CANTIDADC :1147.
5. SPQ_FTR_COL · EJECUTAR_RIPS_JSON_ASYNC marca COMPLETADO aunque GENERAR devuelva KO por result set, no por RAISERROR :4277-4289. SPK_GENERAR_RIPS_JSON no regenera AJUSTE de cápita que no es PGP :190-199.

Descartados (no pedirlos): lista CITPAQ distinta; SPK_RIPS_PREVALIDAR_FTR_CAPI (no existe); valor invertido en paquetizados (ya corregido; el fallo vivo es AT :1147).

Finalidad, causa y modalidad no son un fallo único: cada hoja tiene su default. Unificarlos sería otro alcance, no este.

3. Alcance

Generación del RIPS JSON (evento, masiva, cápita, capitación masiva, PGP, programa, paquete, ajuste y nota) y el trabajo en cola de FTR_COL. No incluye NOTAAJUSTE_MAS.

4. Restricciones

No incluye reescribir las hojas a INSERT SELECT / FOR JSON PATH ni dejar de llamar FNK_LIMPIATEXTO por fila. No cambia el XML DIAN, el RIPS plano TXT, ni radicar CXC. No rehace JSON ya enviados con CUV. No unifica finalidad, causa y modalidad. SPK_RIPS_JSON_NOTAAJUSTE_MAS y NOTAAJUSTE_PGP: SP sin uso desde FTR_COL. Corregir solo si se reactivan.

5. Criterios

1. Un servicio facturado sin código RIPS homologado no desaparece en silencio: o entra al JSON o el usuario ve cuáles faltaron.
2. Una urgencia u hospitalización de más de 48 horas en factura masiva o capitación masiva sí se reporta.
3. Generar el JSON de capitación masiva no cambia HADM.FECHA.
4. En evento, el UPDATE de CUM solo toca medicamentos y códigos vacíos o sin guion: el AND/OR del WHERE va entre paréntesis.
5. En otros servicios de cita (AT), el valor unitario es el del ítem dividido por la cantidad y el valor del servicio es el del ítem.
6. Si la generación devuelve error, el trabajo en cola queda en error y el usuario lo ve; no queda Completado.
7. Un ajuste de cápita que no es PGP vuelve a armar el JSON de esa nota.
8. El tipo de usuario del JSON sale del evento facturado.
9. El CUM sigue una sola cadena; si todo está vacío no inventa código.
10. Una factura evento o PGP sin estos casos sigue generando como hoy.

6. Recomendación

Llevar a comité. Es defecto sobre el proceso rips-json ya documentado: el camino existe y falla. Viable en IXONLINE/SQL, sin pantalla nueva.

Orden sugerido: 1) LEFT JOIN RIPS_CP con rechazo explícito en todas las hojas; 2) quitar el filtro de 48 h en MAS, CAPMASI y NOTAAJUSTE_MAS; 3) sacar el UPDATE HADM de CAPMASI; 4) paréntesis del CUM y valores AT en IND; 5) el async solo marca COMPLETADO si GENERAR no trajo KO; 6) el despachador regenera el AJUSTE de cápita no-PGP.

La reescritura por velocidad (cursores, FNK_LIMPIATEXTO) se deja para un segundo paquete.

7. Sugerencia de código SQL

Especificación para el comité y el desarrollador. No ejecutar desde BA. Contrastar PREVERSION vs última Cerrada antes de implementar.

IXONLINE/SQL. Especificación; no ejecutar desde BA.

1) Hojas SPK_RIPS_JSON_FTR_* / AJUSTE_* / NOTAAJUSTE_* / NDBCR_IND:
   Hoy: INNER JOIN RIPS_CP ON SER.CODIGORIPS = RIPS_CP.IDCONCEPTORIPS
   Esperado: LEFT JOIN RIPS_CP y, si CODIGORIPS queda vacío, no silenciar el ítem (rechazo con mensaje o bitácora de no homologados).

2) SPK_RIPS_JSON_FTR_MAS :1389/:1421, CAPMASI :862/:893, NOTAAJUSTE_MAS :1048/:1080:
   Hoy: AND DATEDIFF(HOUR, HADM.FECHA, HADM.FECHAALTAMED) <= 48
   Esperado: quitar esa condición. Reportar la estancia con su duración real.

3) SPK_RIPS_JSON_FTR_CAPMASI :835-844:
   Hoy: UPDATE HADM SET FECHA = ... si DATEDIFF hora/minuto alta-ingreso < 0
   Esperado: no actualizar HADM desde el generador del JSON. Si hay que corregir la fecha, otro proceso clínico.

4) SPK_RIPS_JSON_FTR_IND :1645-1649:
   Hoy: UPDATE ... SET CODCUM = IUM, CODCUM, SER.CODCUM (sin paréntesis / COALESCE agrupado)
   Esperado: COALESCE(IUM, CODCUM, SER.CODCUM) con paréntesis; no pisar un CUM ya resuelto con vacío.

5) SPK_RIPS_JSON_FTR_IND AT :1147:
   Hoy: vrUnitOS = vrServicio = FTRD.VLR_SERVICI, cantidadOS = CIT.CANTIDADC
   Esperado: vrServicio = VLR_SERVICI; vrUnitOS = VLR_SERVICI / CANTIDADC cuando la cantidad > 0.

6) SPQ_FTR_COL · EJECUTAR_RIPS_JSON_ASYNC :4277-4289:
   Hoy: COMPLETADO si no hay excepción SQL
   Esperado: si GENERAR devuelve KO (result set), ESTADO = ERROR con el mensaje; no COMPLETADO.

7) SPK_GENERAR_RIPS_JSON :190-199:
   Hoy: AJUSTE cápita no-PGP no regenera y RETURN
   Esperado: regenerar el JSON de esa nota (misma hoja que corresponda al documento origen).

Controles en la base de procesos

Variables y servicio FEV-RIPS

Configuración · config-fevrips

CONFIG_GENE_FEV (JSON: procedenciasSinAsync, valorMinimoAsync) decide segundo plano o inmediato; sin variable o JSON inválido → segundo plano. FEVRIPS_MODO=MICROSERVICIO activa FEVRIPS_COLA. El JWT SISPRO se guarda 60 min en TRANSIENT (JWT_RIPS) por usuario.

Invariante: Sin FACTE=2 el motor no genera. Sin CUV en la FV no hay AJUSTE ni NC/ND.

SP: FNK_RIPS_JSON_USAR_ASYNC · (función)

Conf. async: valores por defecto

Configuración · conf-async-discrepancia

Sin CONFIG_GENE_FEV la BD usa segundo plano para todo, pero el diálogo Conf. async abre con todas las procedencias como inmediatas. Guardar sin cambios vuelve todo síncrono. El diálogo no valida permiso USGRUH.

Invariante: Revisar la lista antes de guardar. Cambia la variable de toda la institución.

SP: SPQ_USVGS_COL · ACTUALIZA_DATO

Qué facturas lista el masivo

Proceso propio · filtro-masivo

Pestaña FEV-RIPS: FACTE=2, FDIAN.FTRELECTRONICA=1, FDIAN.PROCEDENCIA FTR/FPOS, SI=0, ESTADO=P, CONTABILIZADA≠0, VR_TOTAL>0, PROCEDENCIA≠CAJA, TIPOANULACION≠NC, YEAR(F_FACTURA)>2024. Validados = CUV lleno; Con Error = existe FTR_MAS_LOG FEVRIPS.

Invariante: Una factura fuera de este filtro no aparece: no es defecto.

Generar RIPS JSON

Proceso propio · generar-json

FE: useRipsJsonAsync. Síncrono RIPS_JSON o INICIAR_RIPS_JSON_JOB → EJECUTAR_RIPS_JSON_ASYNC (polling 15 s, hasta 60 min). Reintenta 3 veces si SQL reporta deadlock. Motor SPK_GENERAR_RIPS_JSON despacha la hoja según CAPITADA+TIPOCAP+TIPOFAC+PROCEDENCIA+PPT.PGP.

Invariante: FACTE=2. GENERAR=NO reusa JSON_ENVIO si existe. SOLO_META no arma payload. Factura anulada o con NC: la pantalla bloquea Generar y Validar.

Marcar, enviar y CUV

Proceso propio · enviar-cuv

MODELO RIPS: MARCAFAC/MARCATODO/MARCAFCXC → envío desde el navegador al servicio FEV-RIPS (endpoint por tipo: CargarFevRips, CargarCapitaInicial/Periodo/Final, CargarNC, CargarNCTotal, CargarND, CargarNotaAjuste) → SET_DATOS (CUV + FRADICA_RIPS solo si ResultState='true'). RVG02 → ConsultasFevRips/RecuperarCUV → SET_DATOS ISVALIDACUV. ZIP: GET_DATOS_XML_ATTACHEDDOCUMENT + GET_CONFIG_EXPORT_RIPS.

Invariante: CUV no es radicado FCXC. Documento con CUV: Validar Ahora bloqueado. Token SISPRO inválido detiene el lote tras un intento de renovación.

Atención y afiliado hacia el JSON

Lo que llega · atencion-a-rips

Usuario: AFI en casi todas las hojas. HADM.TIPOAFILIADO solo en IND SALUD y VALID_CRUZADA; AUTPG.TIPO_USUARIO en programa. AJUSTE_IND y NDBCR_IND siguen en AFI (no HADM). CUM no es una cadena única (ver faq / sps.json). Finalidad TGEN FINALIDAD.DATO1: el default no es único (IND CIT 44 / HADM AC 15; PGP CIT 15 / HADM AC 44; el resto CIT AC 12; AP suele 16; NDBCR HADM AC 15). Causa consultas a menudo '38' (PGP/CAPI/ajustes PGP leen CIT.CAUSAEXTERNA). Modalidad consultas '01' o TGEN.DATO3 (CAPI/PGP). Recién nacido: FNK (1 QXRCN) o #RECIEN en masivas.

Invariante: Sin DOCIDAFILIADO IND no arma. Particular sí se reporta.

SP: FNK_RIPS_JSON_RECIENNACIDOS · (función)

XML FEV de la DIAN

Subproceso unido · dian-xml-fev

El sobre {rips, xmlFevFile} lleva el AttachedDocument en base64. Doble encode provoca FEV001. AJUSTE exige CUV de la FV. FTRE_XML_DESCENLINEA=SI limpia espacios Description/CDATA.

Invariante: FACTE=2 en FV; FNOT.FACTE=2 en NC/ND.

Sin asiento propio

Contabilidad · sin-om-rips

Invariante: Generar JSON no contabiliza.
