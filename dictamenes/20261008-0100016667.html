1. Requerimiento del cliente

Error contable en factura FEV337501 por duplicidad en MCP. La factura FEV337501 presenta un error contable indicando que el comprobante también existe en MCP (contabilidad definitiva). Se solicita revisar la duplicidad entre MCPE y MCP, ya que normalmente no debería permanecer en errados. Soporte validó que el ítem genera un número de comprobante con procedencia FACTURA, pero ese número ya existe con procedencia INV. Se solicita arreglo urgente. Contrastar con el requerimiento de comprobante referencia y sede (REQ 0100016529): validar SPs de contabilización de factura y duplicidad.

INV) salvo reemplazo explícito con mismos metadatos. 3) Tras fallo por colisión de número, FTR queda en estado reintentable (CONTABILIZADA=0 o coherente con MCPE) y no permanece MCPE huérfano junto al MCP de inventario. 4) Diagnosticar errores en Comprobantes errados deja de reportar YA_EN_MCP para el comprobante corregido. 5) Regresión: contabilizar factura financiera y movimiento INV en la misma sede sigue generando números distintos vía secuencia @MCP.

5.0 En palabras simples (negocio)

Hoy la factura puede recibir el mismo número de comprobante contable que ya usó un movimiento de inventario; el sistema la deja en errados (YA_EN_MCP) y no la pasa a libros. Se propone que, al contabilizar la factura, el sistema pida un número realmente libre y, si choca con un comprobante de otro módulo, limpie el intento fallido y permita reintentar sin duplicar en errados y definitivos.

-- AFTER: @MAUX formado con SPK_GENCONSECUTIVO + prefijo sede (~L248-251)
DECLARE @INTENTOS INT = 0
WHILE @INTENTOS < 20
BEGIN
  SET @MAUX = ... -- GENCONSECUTIVO + prefijo sede (lógica actual)
  IF NOT EXISTS (SELECT 1 FROM MCP WHERE NROCOMPROBANTE=@MAUX AND COALESCE(ANULADO,0)<>1)
     AND NOT EXISTS (SELECT 1 FROM MCPE WHERE NROCOMPROBANTE=@MAUX AND COALESCE(ANULADO,0)<>1)
     BREAK
  SET @INTENTOS += 1
END
IF @INTENTOS >= 20 RAISERROR('No fue posible asignar NROCOMPROBANTE libre para factura',16,1)
