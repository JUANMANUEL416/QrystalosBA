1. Requerimiento del cliente

Validar las CXC que no tienen asociados el RECONOCIMIENTO y asociarlas y a las que no identificar e informar para toma de decisión. DETALLE: Se solicita que el sistema agregue validaciones en el recaudo de cartera. Estas validaciones deben aparecer únicamente si la variable PRESUP_CXC_ACTIVADO = 'SI'. Las validaciones son las siguientes: - Cuando se asigna una factura, esta debe validar que tenga un reconocimiento previo. - Cuando se asigna una factura en la ventana, mostrar si esta ha sido enviada o no a presupuesto, indicando su vigencia: Actual, Anterior y Recuperación. - Cuando se quiera aplicar el pago definitivo, debe validar que todas las facturas agregadas al pago estén reconocidas. En caso de que las validaciones 1 y 3 se activen, el sistema debe detener el proceso, mostrar el error y no permitir continuar con el procedimiento.

2. Análisis del coordinador

Paso 0 — ¿Ya existe? No es capacitación. Las capturas corresponden a Administrativo → Cartera → Recaudos: diálogo Asignar facturas (CXCComponent) y botón Aplicar pago (FPAGComponent). Hoy el usuario puede asignar y aplicar sin comprobar reconocimiento presupuestal en ese camino. Caminos del control (recaudos): CONSULTACXC → ADD_FACTURA / carga masiva → ASIGNAR → detalle FPAGD → APLICARPAGO → SPK_PAGOSCXC. Caminos presupuesto relacionados pero distintos: TRAER_FACTURA_PPTO (crear reconocimiento desde factura) y PRESUPUESTO_FPAG (enviar recaudo cerrado a presupuesto); no sustituyen las validaciones en la ventana de recaudo. Clasificación: hueco funcional (desarrollo FE + SQL en SPQ_FPAG_COL condicionado a PRESUP_CXC_ACTIVADO).

5. Cambios propuestos

5.0 En palabras simples (negocio)

Cuando la institución tiene activado presupuesto en cartera, al recaudar no se podrá asignar ni aplicar pagos sobre facturas que no tengan reconocimiento presupuestal confirmado; en la lista de facturas por asignar se verá si ya van a presupuesto y de qué vigencia. Si la variable está apagada, nada cambia.

--    SELECT ..., COALESCE(FTR.ENPRESUPUESTO,0) ENPRESUPUESTO, D.RECO, D.ESTADO ESTADO_RECO,
--           COALESCE(D.VIGENCIA,'Actual') VIGENCIA_PPTO

-- 2) ADD_FACTURA y/o ASIGNAR — tras validaciones actuales:
IF DBO.FNK_VALORVARIABLE('PRESUP_CXC_ACTIVADO') = 'SI'
   AND @INGRESO IN ('CAJA','BANCOS','CXP')
BEGIN
   IF NOT EXISTS ( /* FTR + PTRECO Confirmado para @N_FACTURA */ )
   BEGIN
      SELECT 'KO' AS OK,
             CONCAT('La factura ', @N_FACTURA,
                    ' no tiene reconocimiento presupuestal confirmado. '
                    ,'Revise Presupuesto o traiga la factura antes de recaudar.') AS ERROR;
      RETURN;
   END
END

-- 3) APLICARPAGO — antes de SPK_PAGOSCXC (análogo SPQ_PPTO_REP PRESUPUESTO_FPAG):
IF DBO.FNK_VALORVARIABLE('PRESUP_CXC_ACTIVADO') = 'SI'
   AND @INGRESO IN ('CAJA','BANCOS','CXP')
BEGIN
   IF EXISTS (
      SELECT 1 FROM FPAGD A
      INNER JOIN FTR B ON A.N_FACTURA = B.N_FACTURA
      LEFT JOIN PTRECO D ON B.CONSECUTIVOPTO = D.CONSECUTIVO AND B.RECO = D.RECO
      WHERE A.CNSFPAG = @CNSFPAG
        AND (COALESCE(B.ENPRESUPUESTO,0) = 0 OR D.RECO IS NULL OR D.ESTADO <> 'Confirmado')
   )
   BEGIN
      SELECT 'KO' AS OK,
             'Hay facturas sin reconocimiento presupuestal confirmado. No se puede aplicar el pago.' AS ERROR;
      RETURN;
   END
END
