1. Requerimiento del cliente

Error en fecha de cierre de envío de factura Al cerrar un consecutivo de envío para traslado de factura, el sistema toma la misma fecha de apertura en lugar de la fecha de cierre. Se requiere que el sistema registre correctamente la fecha de cierre. Pasos reportados: 1. Abrir un consecutivo de envío para traslado de factura. 2. Cerrar el envío. Se solicita ajuste de lógica para garantizar trazabilidad de las fechas del proceso de traslado en Facturación.

Criterios de aceptación

1. Al crear un consecutivo de envío (ENT), la columna de fecha de apertura/entrega (F_Entrega) conserva la fecha/hora registrada en ENT.FECHAENTREGA al abrir el envío. 2. Al pulsar Cerrar envío sobre una ENT abierta con detalle (ENTD), el sistema persiste la fecha y hora real de cierre en ENT (campo dedicado) y la muestra en la grilla de Traslados Facturas. 3. Al reabrir el envío (Abrir envío), se limpia la fecha de cierre y el envío vuelve a estado Abierto sin alterar FECHAENTREGA. 4. Un envío cerrado en un día distinto al de apertura muestra fechas de apertura y de cierre diferentes en pantalla. 5. La recepción en cartera/auditoría (PROCESAR_ENVIO / RECIBIR_AUDIFACTU) sigue registrando FECHARECIBE como hoy; no se confunde con la fecha de cierre del envío en facturación. 6. Prueba de regresión: agregar/retirar facturas, imprimir acta, exportar Excel y Crear CxC sobre envío cerrado siguen operando igual.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy, cuando facturación cierra un envío de facturas, el sistema solo marca el envío como «Cerrado» pero no guarda cuándo se cerró; la pantalla sigue mostrando la fecha en que se abrió el envío. Se propone guardar la fecha/hora de cierre al cerrar (y borrarla si se reabre) y mostrarla en la lista de envíos, manteniendo visible la fecha de apertura.

5.1 Detalle técnico — Frontend (Qrystalos2)

  • ENTComponent.vue — En columnas_visibles del AppStore.read sobre ENT: mantener F_ENTREGA desde FECHAENTREGA; agregar F_CIERRE con CONVERT(VARCHAR, ENT.FECHACIERRE, 103) (o equivalente) y columna en columns de la tabla.
  • Tras respuesta OK de CERRAR_ENT, refrescar grilla para mostrar F_Cierre actualizada.
  • Ayuda HelpManualTrasladosFacturas: mencionar F_Entrega = apertura, F_Cierre = cierre del envío (cuando aplique).
  • IMPRIMIR_ENT — Si el acta debe reflejar cierre operativo, usar FECHACIERRE cuando CERRADO=1 en lugar de solo FECHARP de impresión (validar con usuario).

5.2 Detalle técnico — SQL Server

Objeto principal: IXONLINE/SQL · SPQ_ENT_COL, METODO CERRAR_ENT. Tabla ENT.

  • Agregar FECHACIERRE datetime NULL si no existe.
  • En CERRAR_ENT: al pasar a Cerrado, FECHACIERRE = DBO.FNK_GETDATE(); al reabrir, FECHACIERRE = NULL.
  • No modificar FECHAENTREGA en CERRAR_ENT.
  • Históricos: backfill opcional solo si lo acuerda el comité (fuera de alcance por defecto).

5.2.1 Fragmentos SQL (especificación)

Especificación para desarrollo en IXONLINE/SQL. No ejecutar desde Qrystalos BA.

-- IXONLINE/SQL SPQ_ENT_COL · ENT

IF COL_LENGTH('dbo.ENT', 'FECHACIERRE') IS NULL
   ALTER TABLE dbo.ENT ADD FECHACIERRE datetime NULL;
GO

-- METODO CERRAR_ENT — reemplazar UPDATE (concepto):
UPDATE ENT
SET CERRADO = CASE COALESCE(CERRADO,0) WHEN 1 THEN 0 ELSE 1 END,
    FECHACIERRE = CASE COALESCE(CERRADO,0) WHEN 1 THEN NULL ELSE DBO.FNK_GETDATE() END
WHERE CNSENTREGA = @CNSENTREGA;

-- Validación
SELECT CNSENTREGA, CERRADO, FECHAENTREGA, FECHACIERRE, FECHARECIBE, ESTADO
FROM dbo.ENT
WHERE PROCESO = 'FACTURAS' AND COALESCE(CERRADO,0) = 1
ORDER BY FECHAENTREGA DESC;
