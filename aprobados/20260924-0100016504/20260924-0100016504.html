1. Requerimiento del cliente

Se requiere que se agrupen los ítems de las notas crédito cuando son muy grandes: se bloquea el envío a la DIAN y no envía; dice «proceso detenido».

Criterios de aceptación

1. Una NC aplicada con miles de líneas FNOTD (caso referencia CNSFNOT 01C00239078 / factura SMSG89915) encolada desde Notas DB/CR completa la notificación DIAN (FACTE→2) sin quedar detenida en cola ni en error 3 por timeout/volumen de XML. 2. El XML UBL de la NC mantiene cuadre: LineCountNumeric = cantidad de CreditNoteLine emitidas; LegalMonetaryTotal/PayableAmount = FNOT.VR_TOTAL; SUM(LineExtensionAmount líneas) + IVA = encabezado. 3. La agrupación es solo en la capa de emisión (XML y, si aplica, JSON RIPS FEV): no altera FNOTD en base ni el comprobante MCP ya generado al aplicar. 4. NC con pocas líneas (≤ umbral configurable, propuesta 500) se comporta igual que hoy (sin agrupar). 5. Si el fallo actual fuera validación FEV/RIPS («Documento detenido en validación FEV/RIPS»), queda documentado en prueba; este REQ no sustituye el fix de cobertura/tipo usuario (REQ 6436) salvo evidencia en log.

Alcance

Incluye control encolar-dian (Notas DB/CR → FNOT_ENCOLAR → SPK_GENERAR_XML_DIAN) y agrupación de CreditNoteLine; revisión SPK_RIPS_JSON_NDBCR_IND si hay FEV-RIPS en NC. Fuera: reescribir FNOTD al aplicar, notas CxP, SUNAT, cambiar SPK_VALID_CRUZADA_FEV sin evidencia.

5. Cambios propuestos

5.0 En palabras simples (negocio)

Cuando una nota crédito trae miles de medicamentos u otros ítems (como en la captura del REQ), el sistema hoy intenta enviar a la DIAN una línea electrónica por cada fila del detalle y el proceso se detiene. Se propone agrupar esas filas al armar el XML (y el JSON de salud si aplica), igual que ya se hace en parte en las facturas, de modo que el valor total de la nota no cambie pero el archivo sea manejable y la DIAN pueda aceptarla. El detalle contable y de cartera en Qrystalos sigue igual; solo cambia cómo se empaquetan las líneas al notificar.

5.1 Detalle técnico — Frontend (Qrystalos2)

Sin cambio obligatorio de contrato JSON. Opcional (Parcial): en NotasDBCRComponent, al seleccionar una NC con detalle muy grande, mostrar aviso de que la emisión DIAN consolidará líneas (mockup: activo/20260924-0100016504/mockups/mockup-ux-pantalla.html). Encolar sigue usando FNOT_ENCOLAR.

5.2 Detalle técnico — SQL Server

Publicar en PREVERSION: • SPK_GENERAR_XML_DIAN — bloque Detalle CreditNoteLine (#FNOTD_OPT): si COUNT(FNOTD)>@UMBRAL, INSERT agrupado (SUM cantidades/valores) por IDSERVICIO + descripción + VR_UNITARIO + IVA; si no, comportamiento actual 1:1. • SPK_RIPS_JSON_NDBCR_IND — mismas llaves de agrupación en ramas que leen FNOTD cuando el cliente usa FEV-RIPS en NC. • Variable FNOT_NC_AGRUP_UMBRAL (default 500). No modificar: SPK_GENITEMS_NOTACR, SPK_NOTASCXC, SPK_NC_CONTAB_FNOT, FNOT_ENCOLAR.
