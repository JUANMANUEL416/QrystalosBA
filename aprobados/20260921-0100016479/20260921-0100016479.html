5. Cambios propuestos

5.0 En palabras simples (negocio)

Hoy, al bajar el ZIP de tramas para SUSALUD, el mismo paciente/prestación puede llevar diagnósticos diferentes en los archivos de cabecera (DATE), servicios (DSER) y farmacia (DFAR). Se propone que el sistema calcule un solo diagnóstico válido por factura (el de la atención clínica principal) y lo copie de forma consistente a los tres archivos antes de descargar, para que TEDEF/SUSALUD no rechace el envío.

5.2.1 Fragmentos SQL (especificación)

Especificación para desarrollo — no ejecutar desde Qrystalos BA.

-- Fuente referencia: sql_refe/0100016369/SPK_GEN_TRAMAS_PERU.sql — validar cuerpo en PREVERSION DESAIX.

-- Opción B — sincronizar antes de UPDATE TRAMATEX:
UPDATE S SET S.IDDX = D.IDDX
FROM TRAMA_DSER S
INNER JOIN TRAMA_DATE D ON D.IDTRAMA = S.IDTRAMA AND D.NUMDOC_PAGO = S.NUMDOC_PAGO
WHERE S.IDTRAMA = @ENVIO AND COALESCE(S.IDDX,'') <> COALESCE(D.IDDX,'');

UPDATE F SET F.IDDX = D.IDDX
FROM TRAMA_DFAR F
INNER JOIN TRAMA_DATE D ON D.IDTRAMA = F.IDTRAMA AND D.NUMDOC_PAGO = F.NUMDOC_PAGO
WHERE F.IDTRAMA = @ENVIO AND COALESCE(F.IDDX,'') <> COALESCE(D.IDDX,'');

-- Validación (lote @ENVIO):
SELECT 'DATE' T, NUMDOC_PAGO, CORRELATIVO, CORRE_PRESTA, IDDX FROM TRAMA_DATE WHERE IDTRAMA=@ENVIO
UNION ALL
SELECT 'DSER', NUMDOC_PAGO, CORRELATIVO, CORRE_PRESTA, IDDX FROM TRAMA_DSER WHERE IDTRAMA=@ENVIO
UNION ALL
SELECT 'DFAR', NUMDOC_PAGO, CORRELATIVO, CORRE_PRESTA, IDDX FROM TRAMA_DFAR WHERE IDTRAMA=@ENVIO
ORDER BY 2,3,4;
