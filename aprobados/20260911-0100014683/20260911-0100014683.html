1. Requerimiento del cliente

Paridad WEB con Clarion: opción para enviar de forma individual las cuentas de cobro (CXC) que no hayan sido enviadas al módulo de presupuesto, identificar pendientes (equivalente a filtro «No Enviado») y evitar reproceso o duplicación de lo ya enviado. Nota: el texto IX OnLine repite «cuentas por pagar» en el detalle; capturas del caso y módulo del formulario confirman que el alcance es Cuentas por Cobrar.

Criterios de aceptación

1) En WEB, ruta Administrativo → Cuentas por Cobrar → pestaña «Cuentas por Cobrar», con USVGS PRESUP_CXC_ACTIVADO=SI, el usuario puede filtrar cuentas de cobro no enviadas a presupuesto (FCXC.ENPRESUPUESTO=0) y abrir el detalle de una cuenta radicada. 2) Con permiso USGRUH BTN_ENVIAR_PRESUPUESTO_FCXC (MENUQ_ADMINISTRATIVO), aparece el botón «Enviar A Presupuesto» solo si la cuenta está radicada (INDRECIBIDO=1) y aún no fue enviada (ENPRESUPUESTO≠1). 3) Al confirmar, el sistema invoca FCXC_COL · PRESUPUESTO_FCXC con CNSCXC e IDSEDE; responde OK y actualiza ENPRESUPUESTO en cabecera; las facturas del detalle quedan en presupuesto (FTR.ENPRESUPUESTO=1) sin duplicar reconocimientos ya existentes. 4) Si la cuenta ya fue enviada o faltan PTPTO vigente, rubro del plan o variables PRESUP_CCOSTO / PRESUP_TIPORECO=CUENTAC, el sistema muestra el mensaje de error del SP y no marca la cuenta. 5) Comportamiento equivalente al escritorio Clarion (filtro «No Enviado» + acción individual por cuenta), verificable con al menos un caso real ASOCABILIDOS en preproducción.

Percepción cliente

En WEB no existe mecanismo equivalente a Clarion para envío individual (ticket 17461).

Objetivo

Filtrar pendientes, enviar una CXC radicada una sola vez al presupuesto, con mismas validaciones USVGS/PTPTO que el SP.

Invariantes

Solo cuentas radicadas (INDRECIBIDO=1). No reenviar si ENPRESUPUESTO=1. PRESUP_TIPORECO debe ser CUENTAC para este flujo.

5. Cambios propuestos

5.0 En palabras simples (negocio)

En la WEB de Cuentas por Cobrar, el usuario filtra las cuentas que aún no fueron al presupuesto, abre una cuenta ya radicada y pulsa «Enviar A Presupuesto»; el sistema envía sus facturas al módulo presupuestal una sola vez, igual que en Clarion.

5.1 Detalle técnico — Frontend (Qrystalos2)

  • Ruta /admin/CuentasxCobrar · CuentasxCobrarPage → FCXCComponent → pestaña AdmCXC → FCXCAComponent.
  • Confirmar EnviarPresupuestoFcxc: diálogo de confirmación, loading, notify OK/KO, refresco grillas.
  • Visibilidad botón: mostrarBtnEnviarPresupuestoFcxc (PRESUP_CXC_ACTIVADO, permiso, INDRECIBIDO=1, ENPRESUPUESTO≠1).
  • Filtro: checkbox Presupuesto / filtrocxc.ENPPTO (por defecto false → solo no enviadas cuando variable activa).
  • Si el build del cliente no incluye este bloque: merge desde rama con el componente actualizado.

5.2 Detalle técnico — SQL Server

Especificación METODO PRESUPUESTO_FCXC en SPQ_FCXC_COL (referencia sql_refe/0100016283):

  • Parámetros JSON: CNSCXC, IDSEDE.
  • Validaciones: cuenta y detalle existen; PRESUP_CCOSTO y PRESUP_TIPORECO=CUENTAC; PTPTO vigente por F_FACTURA de cada factura en FCXCD.
  • Por cada N_FACTURA: EXEC SPK_ENTREGA_FACTURA_PTTO; verificar FTR.ENPRESUPUESTO=1.
  • Éxito: UPDATE FCXC SET ENPRESUPUESTO=1; respuesta OK.
  • Errores: KO con mensajes por factura o configuración.

5.3 Detalle técnico — Backend (qrystalos.server)

Invocación estándar AppStore.json → SPQ_FCXC_COL. Sin cambio de contrato API si el METODO ya está en el procedimiento desplegado. Ruta qrystalos.server no configurada en BA; impacto vía procedimiento almacenado en SQL Server del cliente.

6. Qué tener en cuenta

  • Integración presupuesto debe estar activa (variables USVGS y PTPTO/rubros PLN).

  • Reintentar envío sobre cuenta ya marcada debe quedar bloqueado en FE y no duplicar en SP.
